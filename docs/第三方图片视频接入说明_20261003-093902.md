# GrsAI 图片与视频供应商接入

本次新增独立供应商 `grsai`，接入 GPT Image 系列图片生成/编辑和 `minimax-h3` 视频生成。供应商 API Key 沿用项目现有加密存储、账户分组和调用 Key 权限控制。用户侧统一归入 Model Bridge 分类，公开文档、调用路径、模型元数据和错误信息不展示渠道名称；具体供应商仅在管理员配置中使用。

## 配置与启用

1. 更新代码并重启服务。启动时 `initDb()` 自动创建 `media_tasks` 和新增计费字段；本次同时提供 `0020_grsai_media.sql` 与 Drizzle 元数据。
2. 管理后台 → 上游账户 → 添加 → **GrsAI（图片 / 视频）**，填写账户名称和 GrsAI API Key。
3. Base URL 留空使用 `https://grsai.dakka.com.cn`；全球节点可填写 `https://grsaiapi.com`。支持根地址、`/v1` 或 `/v1/api` 结尾。
4. 如使用分组，将该供应商账户加入调用 Key 对应分组；未分组的 Key 仅使用未分组账户。调用 Key 的服务商限制选择 **GrsAI**，模型限制可按需选择 `gpt-image-*`、`minimax-h3`。
5. 账户连通性测试使用结果查询探测，不调用付费生成接口。模型广场和 API 文档已加入 GrsAI，并提供图片生成/编辑在线调试。

GrsAI 的 Key 与 MiniMax 官方 Key 分开配置，H3 视频通过 GrsAI 账户调用。

## GPT 图片

| 模型 | 分辨率 | quality | 透明背景 |
| --- | --- | --- | --- |
| gpt-image-2 | 1K | auto | 不支持 |
| gpt-image-2.5 | 1K | auto | 不支持 |
| gpt-image-2-vip | 1K–4K | medium | 支持 |
| gpt-image-2.5-flare | 1K–4K | low / medium / high | 支持 |
| gpt-image-2.5-sunburst | 1K–4K | low / medium / high / xhigh / max | 支持 |

```bash
curl https://你的服务/api/media/v1/images/generations \
  -H "Authorization: Bearer mb-你的调用密钥" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2.5","prompt":"一只橘猫在窗边看雨","size":"1024x1024","response_format":"url"}'
```

编辑接口为 `/api/media/v1/images/edits`，支持 JSON 的 `images` URL/data URL 数组和 multipart 的 `image` 文件；`mask` 支持 URL/data URL 或 multipart 文件。

仅允许 GrsAI 的调用 Key 可使用标准 `/v1/images/generations` 与 `/v1/images/edits`。同时允许 OpenAI 与 GrsAI 的 Key，推荐显式使用 `/api/media/v1`，以确定共用型号的供应商。供应商特有的 `gpt-image-2-vip`、`gpt-image-2.5` 也可在标准路径自动选择 GrsAI。

- `size` 会转换为供应商 `aspectRatio`；基础款支持比例或 1K 像素值，VIP/Flare/Sunburst 使用精确像素值。
- 每次调用 `n=1`；批量生成请提交多个请求。
- `response_format=url` 返回供应商链接；`b64_json` 通过受出站 URL 安全检查、下载大小和超时限制保护的请求获取图片，下载时不附带供应商 Key。
- `stream=true` 返回最终 `image_generation.completed` 或 `image_edit.completed` SSE 事件；不提供中间图。`output_format`、`output_compression`、`partial_images`、`moderation`、`input_fidelity`、`style` 和 `file_id` 暂不支持，提交前返回参数错误。
- 生成提交发生网络超时后不自动重试，避免供应商已受理时重复消费。

## MiniMax H3 视频

```bash
curl https://你的服务/api/media/v1/videos \
  -H "Authorization: Bearer mb-你的调用密钥" \
  -H "Content-Type: application/json" \
  -d '{"model":"minimax-h3","prompt":"电影镜头：橘猫走过雨后的花园，镜头缓慢推进","aspectRatio":"landscape","resolution":"480p","duration":5}'
```

正常受理返回 HTTP 202：

```json
{"id":"media_本平台任务ID","object":"video","model":"minimax-h3","status":"running","progress":0,"results":[],"duration":5,"resolution":"480p","aspectRatio":"landscape"}
```

用创建任务的同一个调用 Key 查询：

```bash
curl https://你的服务/api/media/v1/videos/media_本平台任务ID \
  -H "Authorization: Bearer mb-你的调用密钥"
```

| 参数 | 约束 |
| --- | --- |
| prompt | 必填，描述场景、镜头与声音 |
| aspectRatio | portrait 或 landscape |
| resolution | 480p、768p、1080p |
| duration | 1–15 秒整数；1080p 最多 10 秒 |
| images | 可选，最多 9 张参考图，HTTP(S) URL 或 base64 data URL |
| audios | 可选，最多 3 段参考音频，HTTP(S) URL 或 base64 data URL |
| seed | 可选安全整数 |

也提供标准路径 `/v1/videos`、`/v1/videos/:id`。这是本项目的异步任务接口，请求参数使用 GrsAI H3 格式。

任务状态为 `running`、`succeeded`、`failed`、`violation`，成功后从 `results[].url` 读取视频链接。后台自动查询，客户端可每 5 秒查询一次；出站查询失败后延迟 30 秒再尝试。超出 24 小时仍未完成的任务结束为失败，管理员应核对供应商日志。

## 通用异步接口

图片或视频均可通过 `POST /api/media/v1/api/generate` 提交，使用供应商参数 `images`、`aspectRatio` 等，`replyType` 仅支持 `async`，省略时也按异步处理。

查询使用 `GET /api/media/v1/api/result?id=media_本平台任务ID`。同时提供不带 `/api/grsai` 的别名。查询 id 由本平台生成，供应商 id 保存在数据库，不可直接用供应商 id 查询本平台任务。

## 计费与任务恢复

参考价核查于北京时间 2026-10-03，人民币按项目现有固定系数 0.14 换算为 USD；供应商积分采购成本可能因充值套餐不同而变化。

| 模型 / 分辨率 | 参考人民币 | 默认 USD |
| --- | --- | --- |
| gpt-image-2、gpt-image-2.5 | ¥0.03 / 次 | $0.0042 / 次 |
| gpt-image-2-vip、gpt-image-2.5-flare | ¥0.10 / 次 | $0.014 / 次 |
| gpt-image-2.5-sunburst | ¥0.12 / 次 | $0.0168 / 次 |
| minimax-h3 480p | ¥0.05 / 秒 | $0.007 / 秒 |
| minimax-h3 768p | ¥0.07 / 秒 | $0.0098 / 秒 |
| minimax-h3 1080p | ¥0.15 / 秒 | $0.021 / 秒 |

图片成功按次、视频成功按分辨率和生成秒数计费，继续应用现有分组倍率、钱包及订阅账本。异步任务冻结提交时的价格，提交前检查余额、正在执行任务的预算及 Key 成本配额；任务在用户、Key 和供应商账户维度执行持久化并发限制。

`media_tasks` 保存所有权、原供应商账户/节点、结果和计费状态，不保存明文供应商 Key 或完整参考媒体。后台任务在重启后恢复查询；最终用量通过确定性记录 ID 和 PostgreSQL 事务锁防止重复扣费。结算写入失败会保留待处理任务，稍后重试同一任务的结算。余额或 Key 配额耗尽后，仍可用有效的原 Key 读取已经创建的结果；Key/用户停用、Key 过期和模型权限限制仍会阻止读取。

提交超时不自动重新生成。提交进程中断且未持久化供应商 id 的任务会结束为失败；请核对 GrsAI 日志后决定是否重新提交。改变原账户 Base URL 或删除原账户后，进行中的任务需恢复原账户及节点才能继续查询。

管理员可通过 `model_pricing` 的 `image_request_price`、`video_second_480_price`、`video_second_768_price`、`video_second_1080_price`，或现有 `PRICING_OVERRIDE_FILE` 定制价格。文件示例：

```json
{"version":1,"rules":[{"provider":"grsai","model":"minimax-h3","price":{"input":0,"output":0,"cacheWrite":0,"cacheRead":0,"videoSecond480":0.007,"videoSecond768":0.0098,"videoSecond1080":0.021}}]}
```

## 余额与配额

GrsAI 的公开接口只有生成与结果查询，**没有余额或积分查询接口**，因此上游账户列表的「余额 / 配额」一列不会显示金额。2026-10-03 用账户 Key 对两套官方节点（`https://grsaiapi.com`、`https://grsai.dakka.com.cn`）实测，以下候选路径全部返回 `404 page not found`：

`/v1/api/balance`、`/v1/api/credits`、`/v1/api/quota`、`/v1/api/points`、`/v1/api/wallet`、`/v1/api/me`、`/v1/api/account`、`/v1/api/account/balance`、`/v1/api/user`、`/v1/api/user/info`、`/v1/api/user/balance`、`/v1/api/user/credits`、`/v1/api/consumption`、`/v1/api/consumption-log`、`/v1/api/logs`、`/v1/api/order`、`/v1/api/recharge`、`/v1/dashboard/billing/credit_grants`、`/v1/dashboard/billing/subscription`、`/v1/credits` 等。

grsai.com 控制台里的「余额 / 当前积分」由登录会话渲染，API Key 取不到。因此后台按以下方式呈现：

1. 该渠道账户的单元格只显示「该渠道不提供余额查询」（悬停有说明），不再带任何操作按钮：原「刷新配额」按钮对 GrsAI 只是默默执行连通性探测（`refreshAccountQuota` 对非余额、非 MiniMax 渠道统一回落到 `testAccountConnectivity`），点完提示成功却不写入任何数据，单元格永远停在「未更新」。需要探测时用该行「操作」列已有的「测试连通性」。
2. 批量刷新余额 / 配额时，GrsAI 账户仍会执行连通性检查，结果信息为「该渠道未提供余额 / 配额查询接口，已改为连通性检查」，不再混同为余额刷新成功。
3. 需要掌握消费情况时，用调用记录（图片按次、视频按分辨率和秒数）或 grsai.com 控制台的消耗查询页核对，不要依赖后台余额列。

相关实现：`NO_USAGE_ENDPOINT_PROVIDERS` 与 `hasUpstreamUsageEndpoint`（`src/providers/balance.ts`）、`refreshAccountQuota`（`src/accounts/tester.ts`）、账户表格的 `renderNoUsageEndpoint`（`web/src/views/AccountsView.vue`）；两处渠道列表由 `web/balance.test.ts` 断言保持一致。
