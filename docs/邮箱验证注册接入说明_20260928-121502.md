# 邮箱验证注册接入说明

## 注册流程

1. 管理员在「设置 → 用户注册」开启自助注册；服务同时要求配置 Resend API Key 和发件邮箱，登录页才显示邮箱注册入口。
2. 用户填写邮箱、昵称和密码。服务端保存密码哈希与验证码摘要，调用 Resend 发送 6 位验证码；此时尚未创建可登录账户。
3. 用户在 10 分钟内输入验证码。校验通过后创建或认领未接受的邀请账户，返回登录会话。
4. 60 秒后可重发验证码；新验证码会使旧验证码失效。连续输错 5 次需重新获取。

## 配置

本地开发在 `.env.local`，生产部署在 `.env` 中配置：

```dotenv
RESEND_API_KEY=你的 Resend API Key
RESEND_FROM_EMAIL=noreply@modelbridge.site
```

生产容器通过 `docker-compose.yml` 透传这两项。修改环境文件后需要重启对应后端进程或容器。发件域名必须先在 Resend 完成验证；参见 [Resend 官方域名说明](https://resend.com/docs/dashboard/domains/introduction)。

域名发信能力可用后，在服务器 `.env` 中填写上述两项并重建后端容器，再确认管理员已开启「用户注册」。如需使用 `@modelbridge.site` 收信，还需单独配置收信 MX 记录；邮箱验证码注册只依赖发信能力。

## 接口与保护

- `POST /api/auth/register`：校验注册信息并发送验证码，返回 `202` 与验证码有效期。
- `POST /api/auth/register/resend`：按冷却时间重发验证码。
- `POST /api/auth/register/verify`：校验验证码并创建账户，返回用户会话。
- 密码使用 bcrypt 哈希保存，验证码使用服务端密钥计算 HMAC 摘要；接口有按 IP 限流，验证码尝试次数保存在数据库中。
- 邮件发送失败会返回明确错误，不会创建可登录账户。

本地集成测试使用模拟发信与隔离的 PostgreSQL 测试库，未向真实邮箱发送测试邮件。域名验证后应使用自己的邮箱完成一次真实注册验收。
