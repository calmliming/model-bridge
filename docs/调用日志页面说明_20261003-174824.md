# 调用日志页面说明

## 页面与筛选

- 管理端：侧边栏「调用日志」，路径 `/logs`。
- 用户端：侧边栏「调用日志」，路径 `/app/logs`；仅返回当前用户的记录。
- 支持模型厂家、对话/图片/视频、状态、模型名称或调用别名、Key、日期范围筛选，以及分页。
- 默认每 5 秒自动刷新，可关闭；打开的详情在任务结束、退出「生成中」筛选结果后仍会更新。
- GPT 图片模型（包括第三方渠道的 VIP、Flare、Sunburst 等变体）归 OpenAI；MiniMax H3 归 MiniMax。厂家根据实际模型识别，接入渠道仅作为管理端附加信息。
- 无法根据模型识别且渠道是聚合服务时，标为「未知厂家」。

## 生成生命周期

异步图片/视频直接读取已有 `media_tasks`，可在提交中、生成中、结算中查看进度、输入摘要及规格。任务完成后关联已有用量账本，合并成同一条记录；成功结算后才向日志页提供结果链接。

同步图片生成/编辑在调用上游前写入 `live_requests`，生成中立即可见；完成时在已有计费事务内关联用量记录。不会把进行中的请求写进计费账本，也不会增加重复扣费。同步请求每 30 秒续期，进程中断后超过 90 秒未续期即显示中断错误。

普通对话及历史图片记录继续读取 `usage_logs`。用户接口不返回供应商账号、内部接入渠道和上游请求 ID；分页及筛选均在服务端执行。

## 接口与数据库

- 管理端：`GET /api/admin/logs`。
- 用户端：`GET /api/users/logs`。
- 参数：`page`、`pageSize`（最多 100）、`manufacturer`、`kind`、`status`、`model`、`key`、`startDate`、`endDate`、`id`。
- 新表：`live_requests`。启动时自动幂等初始化；Drizzle 迁移为 `0021_request_logs.sql`，对应快照和 journal 已同步。
- 原有异步任务无需补写数据即可在新页面显示。同步图片的生成中记录从新版后端开始产生；历史完成记录仍可查看。

## 验证

- 全量回归：129 个测试文件、1367 项测试通过，含独立本地 PostgreSQL 数据库验证。
- 覆盖第三方 GPT 归 OpenAI、MiniMax 视频、提交/生成/结算状态、同步图片生成前持久化、完成记录去重、并发请求关联、钱包扣费及用户所有权隔离。
- 前后端类型检查通过，前端构建通过。
- 在本地浏览器验证 OpenAI 厂家筛选，第三方 GPT 图片历史记录正常返回。
