# 上游协议兼容修复

日期：2026-09-12。参考 Sub2API 主线的两项协议修复，按 model-bridge 现有转发路径实现。

## Claude 消息级输出配置

Claude OAuth 直连原先保留 `messages[].output_config`，但固定的 `anthropic-beta` 请求头缺少对应能力开关，上游可能返回 `output_config: Extra inputs are not permitted`。

现增加 `mid-conversation-output-config-2026-07-01`。消息级配置、空正文的 system 控制消息、顶层 `output_config` 及消息顺序均保留；原有请求规范化继续生效。该路径始终使用固定 beta 集合，没有引入按客户端任意 beta 透传或删除控制消息的分支。

实现：`src/providers/claude/relay.ts`。

## Codex 多智能体任务正文

Qwen、智谱、小米与 Kimi K2 的 Responses → Chat 转换原先不识别 `agent_message`。这类条目通常没有 `role`，导致整条任务或回复被跳过；即使带有 `role`，`encrypted_content` 片段中的正文也会丢失。

四条转换路径现在共用 `src/providers/agentMessage.ts`，将 `input_text`、`text` 和 `encrypted_content` 片段按原顺序拼接为一条 user 消息。字符串正文直接保留，包括空白与换行。没有有效文本的条目不生成空消息，并清空跨条目暂存的推理，避免前一轮推理混入下一轮回答或工具调用。

该兼容读取的是自定义 Chat 服务商收到的明文任务字段，不解密原生推理内容。OpenAI、DeepSeek、MiniMax、Kimi K3 和 Sub2API 的原生 Responses 转发未改动。
