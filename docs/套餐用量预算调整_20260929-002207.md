# 套餐用量计算与额度修正

本文件记录撤回 75% 方案的原因。用户随后明确指定对标 OpenCode Go，当前实施规则见[套餐对标 OpenCode 说明](./套餐对标OpenCode说明_20260929-065659.md)。

## 已撤回 75% 额度方案

先前按月费的 75% 设置模型参考用量，混淆了“模型参考价”和“实际采购成本”。在相同币种、钱包按量计费倍率为 1 的前提下，10 美元按量购买可以使用约 10 美元参考用量，而原方案月费 10 美元只提供 7.50 美元参考用量，且同时受五小时、周和月窗口限制，套餐没有价格优势。

因此已删除本次新增的 75% 自动额度规则，并撤回本地尚未售出、仍保持该次修改值的默认套餐下调。原默认月额度 30,000 / 90,000 / 300,000 点暂时恢复，但这些旧值也尚未得到实际成本验证，不应当作最终商业定价依据。本次未更改线上数据库或 Waffo 产品。

## 后续定价依据

用户已确认上游同时包含按 Token 付费的 API 和包月订阅账号池。需要分别取得 API 实际采购价或折扣，以及包月账号类型、数量、每月支出与实际可用容量。模型参考价格不等于采购成本，账号分组的钱包售价倍率也不等于采购折扣。

统一币种与充值换算后，先计算同等支出能购买的按量用量，再结合供应成本、可用容量和服务权益确定套餐额度。套餐需要对稳定使用的用户提供价格或服务优势；轻度、不规律的使用仍可能更适合按量。不在缺少成本数据时任意承诺固定优惠倍率。

## 保留的计量修复

- 根据模型价目表和上游实际报告的输入、输出、缓存及图片用量累计点数，1,000 点对应 1 美元模型参考用量。
- 套餐点数从未按钱包精度舍入的参考费用计算，避免微小缓存费用提前被舍入为零。
- 钱包和旧版金额额度套餐继续采用原有微美元精度。
- 套餐卡片直接显示点数，方便比较具体额度。

本地只有 19 条 DeepSeek 请求，不足以推算混合上游的容量和真实成本。下一步需要上游的采购成本数据。
