# 参考更新采纳说明

日期：2026-09-07。model-bridge 为独立项目；本轮参考 Sub2API 2026-09-01 至 2026-09-07 的发布与修复思路，根据本项目代码重新实现，不建立上游 Git 依赖。

## 已采纳的修复与兼容改进

| 项目 | model-bridge 的实现 |
| --- | --- |
| 工具参数完整性 | Responses → Chat 同时处理参数 delta、arguments.done、output_item.done 和最终 output。流式只补尚未发送的后缀；缓冲结果保留完整参数。支持按 item ID、call ID、output index 关联并行调用。 |
| 流式失败诊断 | 用量日志保存具体错误码、脱敏错误消息和上游请求 ID；管理台可查看。已输出内容后不切号重放，避免重复结果。 |
| 中断与末尾事件 | Chat 转换流提前结束时返回明确错误；缺少末尾空行的 SSE 事件仍被解析，防止遗漏终止事件和用量。 |
| 失败请求用量 | OpenAI、DeepSeek、Kimi、Xiaomi、Qwen、Zhipu 的 Responses 解析器保留 failed/incomplete 中报告的实际用量。 |
| 模型不可用换号 | 对适用的 OpenAI 兼容提供方识别明确的 HTTP 400/404 模型不可用错误，只冷却该模型并尝试其他账号。候选耗尽时保留最后的模型错误；原生 Responses 路径维持原有 SSE 错误封装。普通参数错误不换号。 |
| 并发槽释放 | 账号槽从获取 token 到转发结束统一在 finally 释放；错误处理自身抛异常也不会泄漏槽位。 |
| Claude 版本一致性 | 默认出站 CLI 版本更新为 2.1.263，可配置；billing attribution 的 cc_version 与实际 User-Agent 一致，保留版本后缀、其他归因字段及用户正文。配置下限为 2.1.251。 |
| Kimi 原生 Responses | K3 与短别名使用官方 `/v1/responses`，保留原生工具、图像输入、reasoning 和缓存身份，支持 JSON/SSE。官方当前仅支持 K3，所以 K2 系列继续使用原兼容转换路径。 |
| Astra | 新增 gpt-6-astra 模型发现、模型广场条目和独立价格；清理不支持的采样参数，将 none/minimal 映射为 low，保留原生续聊输入。是否可调用由上游账号决定。 |
| 请求选项透传 | Chat → Responses 保留 reasoning_effort、service_tier、prompt_cache_key、prompt_cache_options、safety_identifier。记录上游实际报告的服务层级，而不是把请求层级当作已执行层级。 |
| 可配置计价 | JSON 价表支持模型通配、基础价格、按推理强度的价格、服务层级倍率、长上下文阈值；30 秒热加载。无效更新保留上一次有效价表，启动时配置文件无效则明确失败。 |
| 历史计价稳定 | 新日志保存结算时的价格快照；调价后历史费用分项仍使用旧快照。旧日志没有快照时沿用原有按时间解析价格的兼容逻辑。 |
| 模型广场价格 | 新增公开基础价格接口，模型广场周期刷新后台实际基础价格；不暴露账号凭据或用户分组加价。 |
| 数据库启动 | 对连接拒绝、数据库启动中等瞬时错误最多尝试 5 次，带退避与连接超时；认证失败、权限错误和 SQL 错误立即失败。 |
| 延迟支付回调 | 对验签、提供商和金额校验均通过的付款，允许本地 expired 订单完成入账；主动查单也可补账。保留行锁、回调去重和已支付幂等规则；管理员取消订单仍沿用原规则。 |

## 配置

### Claude 版本

```dotenv
CLAUDE_CLI_VERSION=2.1.263
```

版本由管理员选择，最低为 2.1.251。环境变量和 Docker Compose 均支持。npm 官方包 `@anthropic-ai/claude-code` 在本轮核查时返回版本 2.1.263。

### 上游请求 ID

自动识别 `x-request-id`、`request-id`、`x-amzn-requestid`、`x-goog-request-id`、`x-correlation-id`。需要自定义时，在管理员账号更新 API 中设置：

```json
{"upstreamRequestIdHeader":"x-provider-trace-id"}
```

接口：`PATCH /api/admin/accounts/:id`，批量更新接口同样支持。设置为 null 恢复默认。敏感头名称和非法头名称会被拒绝，ID 长度上限为 200 字符。

### 价格覆盖文件

```dotenv
PRICING_OVERRIDE_FILE=/app/data/pricing-overrides.json
```

Docker 中可将文件放在当前已有的 `./data` 挂载目录。使用以下空文件启动不会改变现有费率：

```json
{"version":1,"rules":[]}
```

规则格式如下。数值只是自定义售卖规则示例，不代表服务商官方费率：

```json
{
  "version": 1,
  "rules": [
    {
      "provider": "openai",
      "model": "your-model-alias-*",
      "price": {"input": 2, "output": 4, "cacheWrite": 2.5, "cacheRead": 0.2},
      "longContext": {"threshold": 200000, "inputMultiplier": 2, "outputMultiplier": 1.5},
      "serviceTierMultipliers": {"priority": 2, "ultrafast": 3},
      "effortPrices": {
        "high": {"input": 2, "output": 6, "cacheWrite": 2.5, "cacheRead": 0.2}
      }
    }
  ]
}
```

价格单位为美元 / 百万 token。model 匹配实际转发、计费使用的模型名；精确规则优先，通配规则中更具体的优先；每个模型只采用最优的一条规则。文件价格优先于数据库价格，删除规则恢复数据库/内置价格。`longContext: null` 显式关闭该模型的长上下文倍率。

Astra 内置基础价为输入 10、输出 50、缓存写入 12.5、缓存读取 1。总输入（含缓存）大于 272000 时，对整次请求使用输入/缓存 2 倍、输出 1.5 倍。实际报告 Fast/Priority 时再乘 2，Flex 乘 0.5；未报告的服务层级不从用户请求猜测。

其他模型维持本项目原有基础价策略，服务层级倍率可由文件明确配置。Ultrafast 在本轮可核查资料中未取得适用于本项目的统一价格，因此不编造默认倍率；未配置时仍按基础价计费。请求透传不代表上游账号已开通该层级。

本轮未增加按分组强制覆盖用户请求层级的运营策略；当前支持用户显式选择、实际层级记录及管理员价表控制。

## 已有覆盖或不适用项

| 参考项 | 判断 |
| --- | --- |
| DeepSeek 峰谷、GLM-5.3-Flash 独立价格、Fable 5.1 请求规范化 | 本项目已有对应实现，保留现有测试和行为。 |
| 支付履约绕开公共兑换限流 | 本项目支付直接调用钱包事务，不经过公共兑换入口，没有同构问题。 |
| WebSocket 连接池、重放队列、续聊与委派状态 | 本项目无 WebSocket relay 和这类持久化续聊状态，不移植特定架构。 |
| 动态账号模型能力缓存、固定账号模型清单 | 本项目使用静态发现目录和独立账号调度，无对应缓存恢复故障；加入 Astra 静态条目并通过模型不可用换号处理账号差异。 |
| 加密历史恢复、聊天回退时重新发现工具 | 本项目无上述服务端恢复/回退系统；原生 Responses 中对应输入和工具继续透传。 |
| 图片 URL 下载回填 | 本项目图片主路径是 OAuth Responses 的 base64 图片工具结果，没有原生 API Key Images URL 返回分支。没有新增一条不必要的图片出站下载链路。 |
| Sub2API 前端紧凑账号响应、侧边栏与专用监控界面 | 前端布局及接口不同；本轮针对本项目增加实际需要的诊断展示和动态价格刷新。 |

## 数据库与验证

新增 `usage_logs.upstream_request_id`、`service_tier`、`reasoning_effort`、`billing_price`。启动初始化使用幂等 ADD COLUMN，另提供 Drizzle 迁移 `0010_warm_tusk.sql` 与快照，已有业务记录保留。

最终验证：70 个测试文件、557 个测试全部通过；前后端类型检查、前端生产构建、git diff --check 通过。本轮相对此前 512 个测试新增 45 个。测试包括真实 loopback HTTP relay 集成路径。另使用独立临时 PostgreSQL 16 实例验证：初始化和迁移重复执行、Key 部分更新保留映射、两笔并发计费完整入账、价格快照和请求 ID 查询、欠费后鉴权返回 402。临时实例已删除。

服务商模型与真实支付网关没有使用生产凭据联调；使用模拟上游验证协议和回调边界。此前修复的六处问题及回归测试完整保留。
