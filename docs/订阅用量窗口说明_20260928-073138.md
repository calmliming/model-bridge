# 订阅用量窗口与 Waffo 套餐

## 本次确认的规则

套餐购买后按模型、输入、输出及缓存用量加权，归集到用户的对应订阅。同一订阅分组内的多个 API Key 共享计数，不能通过新建 Key 重置额度。用户看到的是使用百分比和重置时间；美元只用于月费和独立的钱包计费。

| 套餐 | 月费 | 标准容量 | 5 小时上限 | 周上限 | 月上限 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Lite | USD 10 | 1× | 2,000 点 | 10,000 点 | 30,000 点 |
| Pro | USD 30 | 3× | 6,000 点 | 30,000 点 | 90,000 点 |
| Max | USD 100 | 10× | 20,000 点 | 100,000 点 | 300,000 点 |

这些数值是本站可编辑的初始容量，不代表任何厂商完整订阅账号的官方额度，也不保证固定请求数或固定 Token 数。上游账号池本身的配额和调度限制仍然生效，上线前需要结合实际订阅账号容量校准。

## 加权计算

复用模型价目表中输入、输出、缓存及图片 Token 的相对权重；已知用量通过现有 `estimateCost` 计算归一化权重，再乘 1,000 得到用量点。套餐点数不受账号分组的钱包售价倍率影响，不是美元余额，不能兑换或提现。

短请求、长上下文、不同模型及缓存命中会消耗不同点数。未知或缺失用量沿用既有计费规则，不凭空补估 Token。每条记录新增 `subscription_id` 和 `subscription_points`，与窗口计数在同一事务提交，方便核对。

用户流水对加权订阅显示用量点数；用户仪表盘的按量费用不累计这些订阅请求的参考金额。旧版金额额度套餐继续按原规则运行。

## 三个窗口

| 窗口 | 起点与重置方式 |
| --- | --- |
| 5 小时 | 首次产生加权用量时开始会话；5 小时后清空该窗口，下一次使用开始新会话。不是每天零点重置，也不是购买后空耗五小时。 |
| 周 | 以订阅初始开始时间为锚点，每 7 天重置；闲置不会移动重置时刻。 |
| 月 | Waffo 订阅使用已验签回调提供的实际账期开始和结束时间；重复通知或取消续订不重置当月用量。手动分配的套餐使用从订阅开始日锚定的 UTC 日历月，正确处理月底和闰年。 |

新请求必须同时有三项剩余额度。任一窗口耗尽时返回 HTTP 429、`subscription_usage_exhausted`、下一可用时间和 `Retry-After`，不会因为钱包有余额而绕过当期订阅窗口。

已获准开始的请求在完成时正常计入当前窗口，不会在结算时转扣钱包。并行或长请求可能使实际用量短时超过上限，页面进度条最多显示 100%；后续请求会被拦截。计数由数据库行锁串行更新，避免并发丢失用量。

Waffo 自动续费成功只推进已付费账期；周窗口独立运行。取消续订保留当前已付费周期，最终终止后结束订阅；续费失败不增加月度额度。
