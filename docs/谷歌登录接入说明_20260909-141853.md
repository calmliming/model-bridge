# 谷歌登录接入说明

统一登录页已接入 Google Identity Services 官方按钮。Google 身份由后端校验，成功后沿用本站普通用户会话，进入 `/app`。

## 启用配置

1. 在 [Google Cloud 的 Clients 页面](https://console.cloud.google.com/auth/clients) 创建 **Web application（Web 应用）**类型的 OAuth 客户端，并填写应用品牌与受众信息。
2. 在 **Authorized JavaScript origins（已获授权的 JavaScript 来源）**中填写实际访问网站的来源，例如 `https://bridge.example.com`。来源包含协议、域名和必要的端口，不包含 `/login` 等路径。本地开发添加 `http://localhost` 和实际前端端口，例如 `http://localhost:5173`。
3. 将 Web Client ID 写入服务器 `.env`：

   ```dotenv
   GOOGLE_LOGIN_CLIENT_ID=1234567890-your-web-client.apps.googleusercontent.com
   ```

4. 安装依赖、构建前端并重启服务。Docker 部署可运行：

   ```sh
   docker compose up -d --build model-bridge
   ```

   直接运行项目时，安装根目录和 `web/` 的依赖，执行 `npm run build --prefix web`，再通过原有进程管理方式重启后端。

5. 打开 `/login`，使用 Google 按钮验证登录。需要允许新用户自助注册时，在现有管理设置中开启注册。本次仅请求基本登录信息，按 Google 的规则，即使项目处于测试状态，也不强制把用户加入测试名单；额外请求其他 OAuth 权限时才不适用这一例外。参见 [Google 受众与测试状态说明](https://support.google.com/cloud/answer/15549945?hl=en)。

本实现使用弹窗和 JavaScript 回调，**无需 Client Secret 或授权重定向 URI**。该 Client ID 独立于 `GEMINI_OAUTH_CLIENT_ID`、`ANTIGRAVITY_OAUTH_CLIENT_ID`；上游账号授权使用的 1455 端口与网站登录无关。官方配置要求见 [Google Identity Services 设置文档](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)。

当前本地 `.env` 未配置 `GOOGLE_LOGIN_CLIENT_ID`，因此登录页会隐藏 Google 入口；此次未改动本地 `.env` 或重启现有服务。

## Google 控制台逐项填写

以登录页 `https://bridge.example.com/login` 为例，以下域名均需替换成实际域名。

1. 打开 Google Cloud，顶部选择已有项目或新建项目，例如 `Model Bridge`。
2. 进入 **Google Auth Platform → Branding（品牌）**。首次使用按引导填写应用名称 `Model Bridge`、用户支持邮箱和开发者联系邮箱。若需要填写应用主页、隐私政策等链接，填写实际可访问的页面。
3. 在 **Audience（受众）**选择 **External（外部）**，用于支持普通 Google 账号。Internal 仅适用于限定在所属 Google Cloud 组织内的应用。
4. 进入 **Clients（客户端）→ Create client（创建客户端）**，按表填写。

| 字段 | 示例 |
| --- | --- |
| Application type / 应用类型 | Web application / Web 应用 |
| Name / 名称 | Model Bridge Web |
| Authorized JavaScript origins / 已获授权的 JavaScript 来源 | `https://bridge.example.com` |
| Authorized redirect URIs / 已获授权的重定向 URI | 本实现留空 |

Branding 中的 **Authorized domains（已获授权的网域）**是另一种字段：本例通常填根域名 `example.com`，不带协议；Clients 中的 JavaScript 来源则是完整的来源 `https://bridge.example.com`。

来源必须匹配用户浏览器实际访问的位置：

| 浏览器登录页地址 | 对应 JavaScript 来源 |
| --- | --- |
| `https://bridge.example.com/login` | `https://bridge.example.com` |
| `https://bridge.example.com:8443/login` | `https://bridge.example.com:8443` |
| `http://localhost:5173/login` | `http://localhost:5173`，另添加 `http://localhost` |
| `http://localhost:3001/login`（本机 Docker 映射端口） | `http://localhost:3001`，另添加 `http://localhost` |

不要在来源里加 `/login`、`/api`、查询参数或通配符。公网网站使用 HTTPS；本地开发可使用 HTTP localhost。前后端分开运行时登记前端来源；通过域名反向代理访问时登记外部域名来源，无需填写容器内部的 3000 端口。参见 [Google OAuth 来源要求](https://developers.google.com/identity/protocols/oauth2/policies)和 [Google 登录设置说明](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)。

创建成功后复制 **Client ID（客户端 ID）**，它以 `.apps.googleusercontent.com` 结尾，写入部署机器上项目根目录的 `.env`。不是 `web/.env`，也不是 Client Secret 或 API Key。

## 检查配置是否生效

重建并启动服务后，通过网站访问 `/api/auth/registration-status`，应看到类似结果：

```json
{
  "enabled": false,
  "turnstileSiteKey": null,
  "googleClientId": "1234567890-your-web-client.apps.googleusercontent.com"
}
```

`googleClientId` 非空说明后端读到了配置。`enabled` 是本站的注册开关，不是 Google 登录开关。允许 Google 新用户注册时，登录管理员后台，在 **设置 → 用户注册 → 开放用户自助注册**中开启开关；已绑定用户不受该注册开关影响。

若没有 Google 按钮，先检查 `googleClientId` 是否仍为 `null`。若 Google 报来源不允许，检查浏览器地址栏的协议、主机名和端口是否与同一个 Client ID 的 JavaScript 来源一致。浏览器侧按钮加载及授权、服务端的身份校验都需要能访问 Google 服务。

## 账号规则

| 账号情况 | 登录行为 |
| --- | --- |
| 新 Google 用户，注册已开启 | 创建余额为零的普通用户，无本地密码 |
| 新 Google 用户，注册已关闭 | 拒绝注册，提示联系管理员邀请 |
| 已绑定 Google 的用户 | 以稳定的 Google `sub` 查找用户；注册关闭后仍可登录 |
| 同邮箱已有密码账号 | 先验证原密码再绑定，保留原用户 ID、密码、昵称、余额、API Key 和用量 |
| 尚未接受邀请的账号 | 先通过邀请链接设置密码，再使用 Google 绑定 |
| 已绑定另一个 Google 身份的邮箱 | 拒绝覆盖原绑定 |
| 已禁用账号 | 拒绝登录 |

Google 邮箱后续变化不会自动修改本站邮箱，也不会把账号合并到另一个同邮箱用户。Google 登录只签发普通用户权限，管理员登录仍使用原有流程。绑定成功时会作废该用户未使用的旧邀请，防止旧邀请重新设置密码。

## 校验与存储

- `POST /api/auth/google/challenge` 返回 5 分钟有效的随机 nonce，并设置 HttpOnly、SameSite=Strict 浏览器 Cookie。HTTPS 使用 Secure 和 `__Host-` Cookie。
- `POST /api/auth/google` 接收 Google ID token。官方 `google-auth-library` 校验签名、签发者、受众与有效期，应用进一步检查已验证邮箱和浏览器 nonce。参考 [Google 服务端 ID token 校验文档](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token)。
- nonce 在账号检查通过、写入用户数据之前原子消费，防止重放。密码确认失败可在有效期内重试，成功登录后清除 Cookie；登录会话通过 JSON 返回，不放进 URL。
- Google 登录和密码确认均限流；跨站请求和表单提交被拒绝。Google 登录使用 Google 身份校验，原有 Turnstile 继续保护密码登录与密码注册。
- 配置 `REDIS_URL` 时跨实例共享 nonce，Redis 故障会拒绝登录。未配置时使用有容量上限的进程内存；多副本部署应配置 Redis。
- CSP 仅在启用 Google 登录时放行 Google SDK 所需路径，并设置支持弹窗的 COOP 与 Referrer-Policy。
- 用户表新增可空的 `google_sub` 和唯一索引。启动时自动兼容旧数据库；迁移 `0011_google_sign_in.sql` 也可重复执行。Google 用户不能通过同邮箱密码注册被覆盖。
