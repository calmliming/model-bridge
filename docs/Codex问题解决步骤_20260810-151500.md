# Codex 503 错误解决步骤

## 问题总结

Codex 报错 `503 Service Unavailable: {"error":"no sub2api account configured"}` 的根本原因是：
1. Model-bridge 服务未运行，或
2. 服务运行但数据库中没有 sub2api 账户配置

## 完整解决步骤

### 第一步：启动 Model-bridge 服务

#### 方式 1：使用 Docker Compose（推荐）

```bash
# 进入项目目录
cd e:/Projects/model-bridge

# 启动所有服务（PostgreSQL + Model-bridge）
docker-compose up -d

# 查看启动日志
docker-compose logs -f model-bridge

# 检查服务状态
docker-compose ps
```

**访问地址：**
- 管理面板：http://localhost:3001
- API 端点：http://localhost:3001/v1/...

#### 方式 2：本地开发模式

```bash
# 确保 PostgreSQL 正在运行
# 如果使用 Docker 单独运行 PostgreSQL：
docker run -d \
  --name postgres \
  -e POSTGRES_USER=model_bridge \
  -e POSTGRES_PASSWORD=your_secure_password_here \
  -e POSTGRES_DB=model_bridge \
  -p 5432:5432 \
  postgres:16-alpine

# 运行数据库迁移
npm run db:generate

# 启动开发服务器
npm run dev
```

**访问地址：**
- 管理面板：http://localhost:3000
- API 端点：http://localhost:3000/v1/...

### 第三步：根据诊断结果采取行动

#### 情况 A：数据库中没有任何账户

**解决方案：添加账户**

1. **通过 Web 管理面板添加**（最简单）：
   - 访问 http://localhost:3001 或 http://localhost:3000
   - 使用 `admin / admin` 登录（记得修改密码！）
   - 进入"账户管理" → "添加账户"
   - 根据你的情况选择 provider 类型

2. **通过 API 导入**：

```bash
# 创建账户配置文件 accounts.json
cat > accounts.json << 'EOF'
{
  "accounts": [
    {
      "provider": "sub2api",
      "name": "Sub2API Gateway",
      "accessToken": "sk-sub2api-your-api-key-here",
      "proxyUrl": "https://api.sub2api.com",
      "weight": 10,
      "notes": "主要 Sub2API 网关"
    }
  ]
}
EOF

# 导入账户
curl -X POST http://localhost:3001/admin/accounts/import \
  -H "Authorization: Bearer YOUR_ADMIN_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d @accounts.json
```

#### 情况 B：有账户但没有 sub2api 类型

这意味着你有其他 provider（如 OpenAI、Claude 等）的账户，但 Codex 正在尝试访问 sub2api。

**解决方案 1：添加 sub2api 账户**（如果你有 Sub2API 服务）

按照上面"情况 A"的步骤添加。

**解决方案 2：更改 Codex 配置使用已有的 provider**

根据你数据库中已有的账户类型，修改 Codex 的配置文件：

```bash
# 查找 Codex 配置文件（通常在用户目录）
# Windows: %USERPROFILE%\.codex\config.json
# Linux/Mac: ~/.codex/config.json

# 示例配置：
{
  "baseURL": "http://localhost:3001/v1",
  "apiKey": "your-model-bridge-api-key"
}
```

**重要**：Codex 默认使用 `/responses` 端点，这会路由到 `sub2api-responses`。如果你想使用其他 provider，需要：

1. **如果有 OpenAI 账户**：
   - 确认 model-bridge 是否支持 `openai-responses` 路由
   - 或者使用其他兼容 Codex 的客户端

2. **如果有 Claude 账户**：
   - Codex 可能不直接支持 Claude 的 `/v1/messages` 端点
   - 考虑使用 Claude Desktop 或 Claude Code 客户端

3. **如果有 DeepSeek/Xiaomi/其他账户**：
   - 检查对应的 responses 路由是否存在：
     - `deepseek-responses`: [src/routes/relay.ts:378](src/routes/relay.ts#L378)
     - `xiaomi-responses`: [src/routes/relay.ts:426](src/routes/relay.ts#L426)
     - 等等

#### 情况 C：有 sub2api 账户但仍然报错

可能的原因和解决方案：

1. **账户状态不是 active**：
   ```sql
   UPDATE accounts SET status = 'active' WHERE provider = 'sub2api';
   ```

2. **账户被冷却**：
   ```sql
   UPDATE accounts SET cooldown_until = NULL WHERE provider = 'sub2api';
   ```

3. **proxyUrl 未配置**：
   - 在管理面板中编辑账户，设置 `Proxy URL`
   - 或通过 SQL：
     ```sql
     UPDATE accounts 
     SET proxy_url = 'https://api.sub2api.com' 
     WHERE provider = 'sub2api';
     ```

4. **API Key 权限问题**：
   ```sql
   -- 检查你的 API Key 配置
   SELECT id, allowed_providers FROM api_keys WHERE id = 'your-key-id';
   
   -- 如果 allowed_providers 不为空且不包含 'sub2api'，需要更新
   UPDATE api_keys 
   SET allowed_providers = ARRAY['sub2api', 'claude', 'openai'] 
   WHERE id = 'your-key-id';
   ```

## 常见问题

### Q: 为什么 Codex 一定要 sub2api？

A: Codex CLI 默认使用 `/responses` 端点，model-bridge 将这个端点路由到 `sub2api-responses` provider。这是设计决策，可能是因为：
- Sub2API 是一个聚合网关，可以提供多种模型
- Codex 期望的响应格式与 Sub2API 兼容

### Q: 我没有 Sub2API，有其他方案吗？

A: 有以下几个选项：
1. **修改 model-bridge 路由**：将 `/responses` 路由到你已有的 provider
2. **使用不同的客户端**：根据你的账户类型选择合适的客户端
3. **自建 Sub2API 兼容服务**：如果你熟悉开发，可以实现一个简单的转发层

### Q: 如何获取 model-bridge API Key？

A: 登录管理面板后，进入"API Keys"页面创建新的密钥。

### Q: 数据库密码忘了怎么办？

A: 如果使用 Docker：
```bash
# 查看 .env 文件中的密码
grep PG_PASSWORD .env

# 或者直接进入容器重置
docker exec -it model-bridge-postgres psql -U model_bridge -d model_bridge
\password model_bridge
```
