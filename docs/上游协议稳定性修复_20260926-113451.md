# Sub2API v0.2.7–v0.2.8 协议与稳定性核查

核查日期：2026-09-26。范围为上一轮更新摘要列出的工具 Schema、流式结束、Gemini/Antigravity 和账号错误分类；不包含视频、插件、运营与备份等新增产品功能。

上游依据：[v0.2.7 发布说明](https://github.com/Wei-Shaw/sub2api/releases/tag/v0.2.7)、[v0.2.8 发布说明](https://github.com/Wei-Shaw/sub2api/releases/tag/v0.2.8)。本轮逐项对照相关提交及本仓库实现，没有使用生产凭据请求模型、修改业务数据或部署服务。

## 已修复

| 问题 | 本地改动 | 主要实现 |
| --- | --- | --- |
| 工具 Schema 的 `required: null` 被严格上游拒绝 | 原生提供方统一清理 Messages、Chat、Responses 的工具定义；仅访问 Schema 节点，保留同名属性、默认值、枚举数据、提示词及调用参数；Sub2API 的通用透传入口不应用这项清理 | `src/providers/toolSchema.ts`、`src/routes/relay.ts`、`src/providers/openai/relay.ts` |
| Chat 转 Anthropic 时根级联合 Schema 无法使用 | 把对象分支的属性合并到对象根节点；`anyOf/oneOf` 的必填字段取交集，`allOf` 取并集；同名字段保留嵌套约束；不修改输入对象 | `src/providers/claude/chat.ts`、`src/providers/toolSchema.ts` |
| Gemini 元组数组和缺失 `items` 导致请求不兼容 | 把 `prefixItems`、数组形式的 `items` 转成单个条目 Schema；异构条目用 `anyOf` 保留类型选项；空缺或布尔 `items` 补字符串条目；递归移除 `required: null` | `src/providers/gemini/relay.ts` |
| Responses 已完成但上游不关闭 HTTP 连接，导致请求与记账挂起 | 原生 Responses 在完整的 `response.completed/failed/incomplete/error` 事件后停止读取并取消该次上游连接；保留终止事件用量；终止后的重复错误不再转发。缓冲 Chat 客户端共用已读记录，不再通过克隆响应体读取两遍 | `src/providers/openai/sse.ts`、`src/routes/relay.ts`、`src/providers/openai/chat.ts` |
| 流内错误状态码丢失或被当成空成功 | 识别内层及事件根级的 `status_code/status`，兼容三位数字字符串；用于缓冲客户端 HTTP 状态和失败分类；普通 `error` 事件也返回错误体；策略阻断继续禁止重试 | `src/providers/openai/chat.ts`、`src/routes/relay.ts` |
| Antigravity 裸 Gemini 模型名直发上游可能 404 | 在清理数值思考预算之前提取深度；按选中账号的 `metadata.antigravityModels` 选择 `low/medium/high/tiered` 变体。Messages 与原生 Gemini 入口共用逻辑，显式 API Key 映射、已有后缀和真实裸名目录项优先 | `src/providers/antigravity/model.ts`、`src/providers/antigravity/relay.ts`、`src/routes/relay.ts` |
| Gemini Go/Python SDK 因 SSE 注释心跳中断 | 根据 User-Agent 或 X-Goog-Api-Client 中的 Google GenAI SDK 标识关闭注释心跳，并滤掉转发中的注释行；适用于 Gemini、Antigravity 原生 Gemini 和 Sub2API Gemini 入口；其他客户端保留原心跳行为 | `src/routes/relay.ts` |

## 边界与取舍

- Anthropic 根级联合展开是兼容投影：能保留字段及字段内的约束，但不能完整表达原来的跨字段分支关联。它只用于 Chat → Anthropic 转换，不改写原生 Anthropic 请求的根级联合结构。
- Gemini 元组转为条目联合后不再表达位置约束；没有可用条目定义时采用字符串兜底。这是该 Schema 方言的兼容处理，不是通用 JSON Schema 等价变换。
- 模型变体仅选择当前账号已经缓存的目录项；没有可用目录时保留原模型名，不猜测型号，也不在转发请求内额外查询目录。目录过旧可通过既有账号配额/目录刷新流程更新。
- 流式提前结束仅用于原生 Responses 上游。Chat → Responses 适配器仍读取后续独立用量块；Anthropic 原生流保留原有完整透传行为。
- HTTP 状态已经发出的流式请求继续以 SSE 错误事件报告失败；显式错误状态用于发送前的缓冲响应及账号失败分类，不尝试重写已发送的 HTTP 状态。

## 无需移植的同名修复

| 上游修复 | 本地核查 |
| --- | --- |
| Kimi Coding Plan 配额耗尽 403 被连续错误计数永久禁用 | 本地 Kimi 是固定 Moonshot API Key 接口，没有上游 Coding Plan 账号类型及对应窗口快照。`classifyUpstreamFailure` 的 403 分支不会禁用账号，也没有连续 403 升级为永久禁用的流程；已有明确并发限制文案走临时冷却。因此没有照搬依赖 Coding Plan 快照的恢复规则 |
| DeepSeek Chat 回退缺少 `reasoning_content` | 本地 Chat 入口转换到 DeepSeek 原生 `/v1/responses`；不存在上游这次修复的 Responses → Chat 回退路径 |
| Gemini 传输错误在同账号退避重试 | 本地原生 Gemini/Antigravity 调用异常后将账号加入已尝试列表并选择下一账号；同账号重试仅属于 Sub2API 网关的既有策略，无原生 Gemini 同构问题 |
| OpenAI HTTP/2 保活容错期限 | 本地使用 Node/Undici，没有上游 Go HTTP/2 的对应设置 |

## 验证

新增 32 项回归测试，覆盖：

- 三类工具协议的空 `required` 清理、用户数据保留、根级联合合并、字面 `__proto__` 属性名及输入不可变性。
- Gemini 两种元组写法、缺失条目定义及显式尾部条目 Schema。
- Antigravity 原生与 Messages 两个入口在预算被清理后仍选择正确变体，以及目录、显式映射与后缀边界。
- 上游故意保持连接不关闭、CRLF 与跨块分帧、结束后取消连接、只记账一次、重复错误不覆盖终止用量。
- `error.status/status_code` 的数字和字符串形式、401/403/429 分类及策略阻断优先级。
- Google Go/Python SDK 不接收注释或注释心跳，JS 客户端保留原行为。

执行结果：

- `npm test`：96 个测试文件通过，914 项测试通过；2 个文件中的 14 项真实数据库测试因未配置专用测试库而跳过。
- `npm run typecheck`：通过。
- `git diff --check`：通过。

本轮没有修改前端或数据库结构；未执行生产环境模型调用、数据库测试或部署。
