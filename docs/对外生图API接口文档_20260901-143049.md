# 对外生图 API 接口文档

本文档说明 Model Bridge 对外开放的图片生成和图片编辑接口。接口兼容 OpenAI Images API 的主要调用方式，调用方使用 Model Bridge 平台 API Key 鉴权。

## 1. 接口概览

假设服务地址为：

```text
https://你的域名
```

| 功能 | 方法 | 推荐路径 | 兼容路径 |
| --- | --- | --- | --- |
| 图片生成 | `POST` | `/v1/images/generations` | `/api/openai/v1/images/generations` |
| 图片编辑 | `POST` | `/v1/images/edits` | `/api/openai/v1/images/edits` |

两组路径的功能和鉴权规则相同。外部 API 客户端建议使用 `/v1/...`；项目内置 Web 前端可使用 `/api/openai/v1/...`。

## 2. 使用条件

调用接口前需要满足以下条件：

1. 管理员已在 Model Bridge 中配置可用的 OpenAI/ChatGPT OAuth 账号。
2. OAuth 账号本身具有图片生成权限。
3. 调用方持有已启用且余额、额度正常的平台 API Key。
4. 服务端未设置 `OPENAI_IMAGE_GENERATION_ENABLED=false`。该配置默认开启。

默认图片模型为 `gpt-image-2`。接口只接受名称以 `gpt-image-` 开头的图片模型，API Key 的模型白名单和模型映射规则仍然生效。

## 3. 鉴权

推荐通过 HTTP Bearer Token 传递平台 API Key：

```http
Authorization: Bearer mb-xxxxxxxx
```

示例：

```bash
curl https://你的域名/v1/images/generations \
  -H "Authorization: Bearer mb-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2","prompt":"一只坐在窗边的橘猫"}'
```

不要在公开网页源码、Git 仓库或可下载的前端配置文件中写入固定 API Key。面向匿名访客的网站应由自己的业务后端保管 Key，并代理调用本接口。

## 4. 图片生成

### 4.1 请求

```http
POST /v1/images/generations
Content-Type: application/json
Authorization: Bearer mb-xxxxxxxx
```

请求参数：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `prompt` | string | 是 | 无 | 图片描述，去除首尾空白后不能为空。 |
| `model` | string | 否 | `gpt-image-2` | 图片模型，必须以 `gpt-image-` 开头。 |
| `n` | integer | 否 | `1` | 生成数量，范围 `1`～`10`。实际可用数量受上游模型限制。 |
| `size` | string | 否 | 上游默认值 | `auto` 或 `宽x高`，例如 `1024x1024`。 |
| `quality` | string | 否 | 上游默认值 | 图片质量，支持值由上游模型决定。 |
| `background` | string | 否 | 上游默认值 | 背景设置。当前 `gpt-image-2` 不支持 `transparent`。 |
| `output_format` | string | 否 | 上游默认值 | 输出格式，例如 `png`、`jpeg` 或 `webp`，以模型实际支持为准。 |
| `output_compression` | integer | 否 | 上游默认值 | 输出压缩率，范围 `0`～`100`。 |
| `response_format` | string | 否 | `b64_json` | 可选 `b64_json` 或 `url`。详见返回说明。 |
| `stream` | boolean | 否 | `false` | 是否使用 SSE 流式返回。 |
| `partial_images` | integer | 否 | `0` | 流式中间图数量，范围 `0`～`3`。 |
| `moderation` | string | 否 | 上游默认值 | 内容审核选项，以模型实际支持为准。 |
| `style` | string | 否 | 上游默认值 | 风格选项，以模型实际支持为准。 |

`gpt-image-2` 的显式尺寸还需要同时满足：

- 宽和高均为 16 的倍数；
- 最长边不超过 3840；
- 长宽比不超过 3:1；
- 总像素数在 655,360～8,294,400 之间。

请求示例：

```json
{
  "model": "gpt-image-2",
  "prompt": "一只坐在窗边的橘猫，午后阳光，写实摄影风格",
  "size": "1024x1024",
  "quality": "high",
  "output_format": "png",
  "response_format": "b64_json",
  "n": 1
}
```

### 4.2 非流式响应

当 `stream=false` 时返回 JSON：

```json
{
  "created": 1788246000,
  "data": [
    {
      "b64_json": "iVBORw0KGgoAAA..."
    }
  ],
  "output_format": "png",
  "quality": "high",
  "size": "1024x1024",
  "model": "gpt-image-2",
  "usage": {
    "input_tokens": 123,
    "output_tokens": 456
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `created` | Unix 时间戳，单位为秒。 |
| `data` | 图片结果数组。 |
| `data[].b64_json` | 当 `response_format=b64_json` 时返回的图片 Base64 数据，不含 Data URL 前缀。 |
| `data[].url` | 当 `response_format=url` 时返回。当前实现返回 `data:image/...;base64,...` Data URL，并非长期有效的公网 HTTP 地址。 |
| `data[].revised_prompt` | 上游返回时才存在，表示修订后的提示词。 |
| `output_format`、`quality`、`size`、`model` | 图片元数据；上游未提供的可选字段可能省略。 |
| `usage` | 上游提供时返回的用量信息。 |

前端展示 Base64 图片：

```js
const imageSrc = `data:image/png;base64,${result.data[0].b64_json}`
document.querySelector('#result').src = imageSrc
```

如果请求使用 `response_format: "url"`，可以直接使用：

```js
document.querySelector('#result').src = result.data[0].url
```

## 5. 图片编辑

图片编辑支持 `multipart/form-data` 和 JSON 两种请求格式。推荐浏览器上传本地文件时使用 multipart。

### 5.1 multipart 文件上传

```bash
curl https://你的域名/v1/images/edits \
  -H "Authorization: Bearer mb-xxxxxxxx" \
  -F "model=gpt-image-2" \
  -F "prompt=把天空替换成极光，保留前景建筑" \
  -F "size=1024x1024" \
  -F "response_format=b64_json" \
  -F "image=@./source.png"
```

multipart 字段：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `image` | file/string | 是 | 待编辑的原图。多个输入可使用重复的 `image` 字段或 `image[0]`、`image[1]`。 |
| `mask` | file/string | 否 | 遮罩图片。 |
| `prompt` | string | 是 | 编辑要求。 |
| 其他参数 | string | 否 | 与图片生成接口一致。`n`、`stream` 等表单字符串会被转换为对应类型。 |

每个 multipart 文件最大为 20 MB，整个请求体最大为 64 MB。

### 5.2 浏览器上传示例

```js
async function editImage(file, prompt, apiKey) {
  const form = new FormData()
  form.append('model', 'gpt-image-2')
  form.append('prompt', prompt)
  form.append('response_format', 'url')
  form.append('image', file)

  const response = await fetch('/api/openai/v1/images/edits', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${apiKey}`,
    },
    body: form,
  })

  const result = await response.json()
  if (!response.ok) {
    throw new Error(result.error?.message || result.error || '图片编辑失败')
  }
  return result.data[0].url
}
```

使用 `FormData` 时不要手动设置 `Content-Type`，浏览器会自动写入正确的 multipart boundary。

### 5.3 JSON 请求

`image` 可以是图片 URL、Data URL、文件 ID 对象或数组：

```json
{
  "model": "gpt-image-2",
  "prompt": "把天空替换成极光",
  "image": {
    "image_url": "data:image/png;base64,iVBORw0KGgoAAA..."
  },
  "response_format": "b64_json"
}
```

也可使用：

```json
{
  "prompt": "融合两张参考图的风格",
  "images": [
    { "image_url": "https://example.com/reference-1.png" },
    { "file_id": "file_xxxxxxxxx" }
  ]
}
```

遮罩仅支持 `mask.image_url`，不支持 `mask.file_id`。

## 6. Web 图片生成示例

同域 Web 应用可以这样调用：

```js
async function generateImage(prompt, apiKey) {
  const response = await fetch('/api/openai/v1/images/generations', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${apiKey}`,
    },
    body: JSON.stringify({
      model: 'gpt-image-2',
      prompt,
      size: '1024x1024',
      response_format: 'url',
    }),
  })

  const result = await response.json()
  if (!response.ok) {
    const message = result.error?.message || result.error || '图片生成失败'
    throw new Error(message)
  }
  return result.data[0].url
}

const src = await generateImage('水彩风格的江南小镇', userApiKey)
document.querySelector('#result').src = src
```

跨域 Web 应用还需要服务端或反向代理配置允许的 CORS 来源、请求方法和 `Authorization` 请求头。当前项目同域部署不依赖 CORS；不建议无条件向所有来源开放 CORS。

## 7. 流式响应

请求设置 `stream=true` 时，响应类型为 `text/event-stream`。

图片生成可能出现以下事件：

| SSE 事件名 | 说明 |
| --- | --- |
| `image_generation.partial_image` | 中间图片，设置 `partial_images` 后可能返回。 |
| `image_generation.completed` | 最终图片。 |
| `error` | 生成失败。 |

图片编辑对应事件名为：

- `image_edit.partial_image`
- `image_edit.completed`
- `error`

流式调用示例：

```bash
curl -N https://你的域名/v1/images/generations \
  -H "Authorization: Bearer mb-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model":"gpt-image-2",
    "prompt":"未来城市夜景",
    "stream":true,
    "partial_images":2,
    "response_format":"b64_json"
  }'
```

完成事件示例：

```text
event: image_generation.completed
data: {"type":"image_generation.completed","created_at":1788246000,"b64_json":"iVBORw0KGgoAAA...","output_format":"png","size":"1024x1024","model":"gpt-image-2"}
```

浏览器原生 `EventSource` 不能发送 POST 请求和自定义 `Authorization` 请求头，因此 Web 端流式调用应使用 `fetch()` 读取 `ReadableStream`，或由业务后端代理。

## 8. 错误处理

### 8.1 图片接口结构化错误

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "invalid_image_request",
    "message": "prompt is required"
  }
}
```

### 8.2 常见 HTTP 状态码

| HTTP 状态 | 常见原因 |
| --- | --- |
| `400` | 缺少 `prompt`、编辑接口缺少图片、参数范围错误、尺寸不合法、内容策略拒绝。 |
| `401` | 缺少 API Key、Key 无效/禁用/过期，或 Key 所属用户不可用。 |
| `402` | 余额不足。 |
| `403` | 生图功能被关闭，或 API Key 无权使用 OpenAI/指定模型。 |
| `413` | 请求体超过服务限制。 |
| `429` | API Key 额度、速率或并发限制已达到。 |
| `502` | 上游未返回图片或返回了无效结果。 |
| `503` | 暂无可用上游账号，或计费记录失败导致响应被拦截。 |

已知错误码：

| 错误码 | 说明 |
| --- | --- |
| `invalid_image_request` | 图片请求参数不合法。 |
| `image_generation_disabled` | 服务端关闭了生图能力。 |
| `content_policy_violation` | 请求被内容策略拒绝。 |
| `image_generation_no_output` | 上游完成请求但没有返回图片。 |

调用方应同时判断 HTTP 状态码和响应体，不应只判断响应体中是否存在 `data`。

## 9. 接入建议

- 服务端调用：直接使用 `/v1/images/generations` 和 `/v1/images/edits`。
- 同域前端：可以使用 `/api/openai/v1/...`，并让登录用户提供自己的平台 API Key。
- 公网匿名前端：通过业务后端代理，避免暴露平台 API Key，并在代理层增加用户鉴权、频率限制和提示词长度限制。
- 图片持久化：`response_format=url` 当前返回 Data URL；如果需要长期公网 URL，调用方应将 Base64 图片上传至自己的对象存储，再返回 CDN 地址。
- 超时控制：生图通常比文本请求耗时更长，反向代理、负载均衡器和前端请求应设置足够的超时时间。
- 失败重试：仅对网络错误、`502` 或 `503` 做有限次数的退避重试；不要自动重试 `400`、`401`、`402` 或 `403`。

## 10. 最小联调检查

```bash
curl https://你的域名/health
```

服务正常时返回：

```json
{"status":"ok","service":"model-bridge"}
```

然后使用有效 API Key 发起最小生图请求：

```bash
curl https://你的域名/v1/images/generations \
  -H "Authorization: Bearer mb-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"一朵白色的花","response_format":"b64_json"}'
```

如果响应包含非空的 `data[0].b64_json`，说明 API、鉴权、账号调度和上游生图能力均已连通。
