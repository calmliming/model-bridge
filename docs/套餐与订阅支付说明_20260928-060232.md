# 套餐与订阅支付说明

> 套餐已按后续确认改为加权用量百分比与 5 小时 / 周 / 月窗口，当前规则及已创建的 Waffo 产品见[订阅用量窗口说明](./订阅用量窗口说明_20260928-073138.md)。本文下方的初始额度表保留为旧版记录，支付接入配置部分继续适用。

## 初始套餐（旧版记录）

管理端「订阅套餐」和用户端「套餐商店」共用响应式卡片，支持手机单列、平板和桌面多列及深色样式。

| 套餐 | 月费（USD） | 每日额度 | 每周额度 | 每 30 天额度 |
| --- | ---: | ---: | ---: | ---: |
| Lite | $10 | $2 | $10 | $30 |
| Pro | $30 | $6 | $30 | $90 |
| Max | $100 | $20 | $100 | $300 |

价格采用本次确认的 $10 / $30 / $100；额度是可编辑的初始值。三个窗口独立计算，沿用现有订阅优先、额度不足则走钱包的计费规则。Waffo 按自然月续费，服务到期时间以已验签通知的实际账期为准；用量窗口仍为滚动 1 / 7 / 30 天。

首次启动时生成缺少的三档套餐，之后不会覆盖编辑结果、重新上架或复活已删除的套餐。优先绑定最早建立的账号分组；无分组时创建「订阅套餐」分组，需要管理员添加上游账户。未关联 Waffo 产品、未配置支付或分组未配置账户时，用户不能下单。

按量充值提供 $10 / $30 / $50 / $100 / $200 五个快捷到账额度，并保留自定义金额。它们是站内 USD 额度，支付宝实际人民币付款继续使用既有兑换比例，不是固定美元人民币汇率。

## Waffo 配置

使用 [Waffo 官方认证协议](https://docs.waffo.ai/api-reference/authentication) 和 [Create Checkout Session](https://docs.waffo.ai/api-reference/endpoints/orders/create-checkout-session) REST API。

1. 在 Waffo 商户控制台创建 Lite、Pro、Max 三个 **monthly 订阅产品**，使用 USD，关闭试用。不要关联 onetime、weekly 或 yearly 产品。正式环境需要对应产品已发布。
2. 在项目根目录的 `.env.local`（本地）或部署环境（生产）配置以下变量。Docker Compose 已透传这些变量。

```dotenv
WAFFO_MODE=test
WAFFO_MERCHANT_ID=MER_你的商户ID
WAFFO_STORE_ID=STO_你的商店ID
WAFFO_PRIVATE_KEY=你的当前环境API私钥
WAFFO_WEBHOOK_PUBLIC_KEY=你的当前环境通知验签公钥
WAFFO_SUCCESS_URL=https://你的域名/app
```

私钥、公钥使用 PEM，可用字面量 `\n` 表示换行。`WAFFO_MODE` 为 `test` 或 `prod`，必须与 API 私钥、公钥和产品所在环境一致。配置只留在服务端，不通过前端读写密钥。

`WAFFO_SUCCESS_URL` 可选，但填写时必须是 HTTPS 绝对地址。Waffo 支付页点击 Done 后才返回该地址；页面跳转本身不会开通订阅。

3. 重启服务。在后台「订阅套餐 → 编辑套餐」分别填写对应的 `PROD_…` 产品 ID，并选择用于服务的账号分组。
4. 确认「设置 → 在线支付」已开启。关闭开关只阻止新下单，不阻止既有付款通知和续订同步。
5. Waffo 通知地址设为：`https://你的域名/api/payment/callback/waffo`。本地联调需要可接收通知的 HTTPS 地址。
6. 按 [官方 Webhook 文档](https://docs.waffo.ai/api-reference/webhooks) 订阅这些事件：

```text
subscription.activated
subscription.payment_succeeded
subscription.renewed
subscription.recovered
subscription.canceling
subscription.uncanceled
subscription.canceled
subscription.past_due
```

7. 使用 Waffo 测试环境完成一次下单、付款、回调开通及取消续订，再配置正式环境。当前本地没有商户密钥和产品 ID，因此已完成代码与本地自动化验证，尚未完成真实 Waffo 沙箱或正式交易验收。

## 支付与订阅行为

- 登录用户在卡片上选择订阅，服务端读取套餐价格并创建 Waffo 会话；客户端不能传入价格或指定其他用户。
- 服务端签名请求锁定价格、USD 币种、禁止试用，并携带不可猜测的本地订单关联信息。税费以 Waffo 收银台为准。
- 返回 Waffo 收银台链接；用户打开付款后可返回点击「刷新付款状态」，重新聚焦页面也会自动刷新。
- 只有验签成功、商店和环境匹配、订单元数据匹配、价格与周期一致的订阅事件才授予服务权限。不依据邮箱认领订单，不依据回跳 URL 或单笔支付事件重复开通。
- 验签保留原始 JSON 字符串，采用 RSA-SHA256，允许官方重试所需的 45 分钟时间窗口。事件去重和权益变更在同一数据库事务中提交；失败返回非 2xx，让 Waffo 重试。
- 续期更新绝对到期时间，不累加通知次数。乱序旧事件不能缩短或重新激活已终止的订阅。
- 取消续订保留当前已付费周期；最终终止才收回权限。扣款失败不增加新的服务周期。
- Waffo 订阅不充值钱包，也不能通过旧余额购买接口绕过 Waffo。既有钱包套餐仍按原方式购买。
- 同一用户、同一分组的待付款会话会复用；已有 Waffo 订阅时不重复创建自动扣费合同。有关联 Waffo 订单的套餐不能直接删除，应下架并先处理远端订阅。
- 用户可以打开 [Waffo 客户门户](https://pancake.waffo.ai/buyer) 管理续订。当前不提供站内换档和退款操作；退款类通知仅审计，不自动计算部分退款对应的服务折算。需要终止服务时，在 Waffo 终止订阅并由终止事件同步。

## 弹窗与适配

通用 `UiModal`、确认对话框 `DialogHost` 和 API 文档授权弹窗都不再响应遮罩点击关闭。关闭按钮、取消按钮及原有 Escape 行为保持可用。弹窗高度使用动态视口单位，内容在弹窗内滚动。

## 验证

- Waffo 请求签名、原始正文验签、环境与商店隔离、过期签名、收银台 URL 校验、身份绑定和失败通知重试的自动化测试。
- 独立本地 PostgreSQL 测试数据库，每个测试文件使用独立 schema；验证迁移重放、默认套餐不覆盖修改、并发下单、通知去重、取消续订、过期付款与余额隔离。
- 前后端 TypeScript 检查与 Vite 构建。
- 浏览器验证管理端卡片、用户商店、充值快捷额度和自定义金额，以及外部点击不关闭弹窗。截图位于 `artifacts/billing-20260928/`。

本次最终结果：107 个测试文件、1090 项测试全部通过（包含 opt-in PostgreSQL 数据库测试），前后端类型检查、Vite 构建、`docker compose config --quiet` 和 `git diff --check` 均通过。初次并行数据库回归触发默认超时，最终改为单 worker，并给数据库初始化和用例足够的等待时间：

```sh
# TEST_DATABASE_URL 必须指向本机、名称以 _test 结尾的独立测试数据库。
npm test -- --maxWorkers=1 --minWorkers=1 --testTimeout=30000 --hookTimeout=60000
```
