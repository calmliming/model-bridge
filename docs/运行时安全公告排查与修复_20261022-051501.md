# 运行时安全公告排查与修复

核查时间：2026-10-22，Asia/Shanghai。范围：本仓库源码、锁文件、构建与部署配置、宿主机开发工具，以及本次实际构建运行的应用和更新器容器。

## 结论

- **Node.js 确认受影响，项目范围内已修复。** 原 Dockerfile 和 `.nvmrc` 固定 24.19.0；核查开始时宿主机实际为 24.22.0。项目通过原生 `fetch` 请求模型、OAuth、验证码等上游，存在 HTTPS、连接复用和自动 Brotli 解压路径。现统一至 24.22.1，并实测容器内运行进程。
- **Go 辅助程序确认受影响，更新器已修复。** 原 `docker:27-cli` 中 CLI、Compose、Buildx 均由修复基线之前的 Go 构建。改用官方 `docker:29.9.2-cli` 的程序，三者均核实为 Go 1.26.10 构建。本项目没有自有 Go 程序需要重编译。
- **PHP 未使用。** 没有 PHP 源码、Composer 清单或 PHP 服务；检查的应用、更新器、PostgreSQL 容器均没有 PHP 解释器。两项 PHP 公告在本项目没有触发路径。
- **共享 Docker Desktop 仍待更新。** 依用户明确选择，本次保留该共享环境，详见下文。

发行版补丁核查：原 Docker 27 CLI 基础系统为 Alpine 3.21.3。查询 Alpine 3.21 的 aarch64 包索引，`nodejs` 为 22.23.2-r0，其安全数据库未列此次 Node 修复；Alpine 3.24 索引中的 Node 也只有 24.18.1-r0。没有依据将这些包视为完成此次公告修复，所以更新器没有继续依赖不固定版本的 `apk add nodejs`。[Alpine 安全数据库](https://secdb.alpinelinux.org/v3.21/main.json)

容器版本核验同时检查了 `/proc/1/exe --version`：应用和更新器实际启动的 Node 均为 24.22.1，内置 Undici 7.30.1、OpenSSL 3.5.9。Brotli 组件版本字符串仍为 1.2.0，不能仅靠这个字符串判断 Node 安全补丁状态。

宿主机现有终端可能仍继承旧 Node 的 PATH；本 Codex 执行环境直接运行 `node` 仍解析到 24.22.0。所有本次 Node 验证均先执行了 `nvm use`，实际使用 24.22.1；继续使用已有终端开发时也须在仓库内执行 `nvm use`。没有替换旧版本二进制或声称已热更新其他进程。

## 各风险的触发路径与限制

| 公告 / 风险 | 当前项目路径与判断 |
| --- | --- |
| PHP CVE-2026-109618、109619 | 无 PHP 源码、依赖清单、解释器或 Web 服务，未使用，无触发路径。 |
| Node CVE-2026-111497：Brotli 解码 | **存在。** `src/http/upstream.ts` 调用全局 `fetch`；OAuth、邮件、验证码等模块也有直接 `fetch`。实际 HTTPS 请求会发送 `Accept-Encoding: br, gzip, deflate`，并自动解压。对 Anthropic 的真实无凭据请求收到 `Content-Encoding: br`，正文成功读取。不能用“没有显式 Brotli API”排除影响；已升级 Node。 |
| Node CVE-2026-105483、106069、106072：TLS 主机名 / IPv4 验证 | 有 HTTPS 上游、OAuth 和 Google 登录公钥获取路径，旧 Node 24 位于受影响范围。特制主机名是否能进入某个调用，仍取决于 URL 规范化、上游白名单及管理员配置，未通过漏洞利用证明每条分支可达。升级后验证可信连接成功、不可信证书和主机名不匹配被拒绝。 |
| Node CVE-2026-105481：Keep-alive 响应混淆 | `fetch`、Undici Agent / ProxyAgent 存在连接复用路径；已通过 Node 更新覆盖。未进行攻击性连接混淆复现。 |
| Node CVE-2026-105482：`dns.resolve` 的 NUL 截断 | 旧 Node 24 版本受影响；项目出站校验使用 `dns.promises.lookup`，未发现项目直接调用 `dns.resolve*` 处理外部输入。没有把“未发现直接调用”视为整个运行时安全证明，随 Node 更新覆盖。 |
| Node CVE-2026-106074：快照 / SEA 随机数缓存 | 未使用用户自建启动快照、SEA 或相关构建选项，当前启动方式为普通 Node + tsx；未发现对应触发条件。 |
| Node CVE-2026-106070：ZipFile | 公告仅列 Node 26；项目使用 Node 24，且未使用该 API。 |
| Node CVE-2026-106071：Permission Model 通配符 | 公告仅列 Node 26；项目使用 Node 24，未启用 Permission Model。 |
| Node CVE-2026-106073：`fs.realpathSync` 权限绕过 | 旧 Node 24 版本受影响，但项目未使用 `--permission` 等权限模型选项；没有依赖该机制作为隔离边界。随 Node 更新覆盖。 |
| Go CVE-2026-111943：更新器 Docker 工具 | **存在 TLS 客户端路径。** CLI / Compose / Buildx 可访问镜像仓库或远端服务。已采用修复后的官方二进制；在新更新器内执行 Docker Hub `manifest inspect` 成功，且可与现有宿主机 Docker API 通信。仅替换 Go 工具链而不替换二进制无法修复这些程序。 |
| Go：esbuild 辅助程序 | 锁定的上游最新版仍为 0.28.2；宿主机和运行镜像二进制含 `go1.26.5` 字符串，但 `go version -m` 无法读取其构建信息，工具链版本证据存在这一限制。项目经 tsx 使用其本地转换服务，没有使用 esbuild 的 TLS 客户端或客户端证书验证功能；上游服务器源码使用 `ServeTLS` 提供服务，不能据此推断调用了受影响的 `Certificate.Verify`。本次未确认项目内触发路径，未替换或自行重编第三方 esbuild。[上游服务实现](https://github.com/evanw/esbuild/blob/v0.28.2/pkg/api/serve_other.go) |

依赖补充：根锁文件的独立 `undici` 包为 7.30.0，源码仅从它导入 Agent / ProxyAgent / Dispatcher；响应解码来自 Node 的全局 `fetch`，升级后的内置版本为 7.30.1。此次 Node 公告包含 Undici 依赖修复；没有把独立包版本与内置版本混为一谈，也未扩大为所有 npm 包升级。项目没有使用独立包的 `fetch`、EventSource 或 SRI API。[Undici 内容编码公告](https://github.com/nodejs/undici/security/advisories/GHSA-xjj6-f33q-929c)
