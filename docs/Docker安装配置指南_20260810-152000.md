# Model-bridge Docker 安装和配置指南

## 第一步：安装 Docker Desktop（Windows）

### 下载和安装

1. **下载 Docker Desktop**：
   - 访问：https://www.docker.com/products/docker-desktop/
   - 点击 "Download for Windows"
   - 或直接下载：https://desktop.docker.com/win/main/amd64/Docker%20Desktop%20Installer.exe

2. **运行安装程序**：
   - 双击 `Docker Desktop Installer.exe`
   - 勾选 "Use WSL 2 instead of Hyper-V"（推荐）
   - 点击 "Ok" 开始安装
   - 安装完成后，点击 "Close and restart"

3. **首次启动**：
   - 安装完成后，Docker Desktop 会自动启动
   - 接受服务协议
   - 可以跳过登录（点击 "Skip"）
   - 等待 Docker Engine 启动完成（右下角图标变绿）

### 验证安装

打开 PowerShell 或命令提示符，运行：

```powershell
docker --version
docker-compose --version
```

应该看到类似：
```
Docker version 24.x.x, build xxxxx
Docker Compose version v2.x.x
```

## 第二步：配置 Model-bridge

### 1. 设置数据库密码

打开 `e:\Projects\model-bridge\.env` 文件，找到并修改：

```env
# 设置一个强密码
PG_PASSWORD=your_strong_password_here_123456

# 建议同时修改管理员密码
ADMIN_PASSWORD=your_admin_password_here
```

**重要**：将 `your_strong_password_here_123456` 替换为你自己的密码！

### 2. 验证配置文件

确保 `.env` 文件包含以下内容：

```env
ENCRYPTION_KEY=1c4301fa86e6d9775c109bdb8a1a09c38fab3b3e0a587cc635ff33e930a71497
JWT_SECRET=c9fa0225687c38f9c57983c3485e5c1a9cc6f616d082967f9df384e8a8ca8908

PG_USER=model_bridge
PG_PASSWORD=your_strong_password_here_123456
PG_DATABASE=model_bridge
DATABASE_URL=postgresql://model_bridge:your_strong_password_here_123456@localhost:5432/model_bridge

ADMIN_USERNAME=admin
ADMIN_PASSWORD=your_admin_password_here
```

## 第三步：启动 Model-bridge

### 打开 PowerShell 或命令提示符

```powershell
# 进入项目目录
cd e:\Projects\model-bridge

# 启动所有服务（PostgreSQL + Model-bridge）
docker-compose up -d

# 等待几秒钟，然后查看状态
docker-compose ps

# 查看日志（确认启动成功）
docker-compose logs -f model-bridge
```

### 预期输出

正常启动后，你应该看到：

```
[model-bridge] Server listening on http://0.0.0.0:3000
[model-bridge] PostgreSQL connected
[model-bridge] Admin user created: admin
```

按 `Ctrl+C` 退出日志查看（服务继续在后台运行）。

### 检查服务状态

```powershell
# 检查容器状态
docker-compose ps

# 应该看到：
# NAME                     STATUS
# model-bridge             Up
# model-bridge-postgres    Up (healthy)
```

## 第四步：访问管理面板

### 1. 打开浏览器

访问：**http://localhost:3001**

### 2. 登录

- 用户名：`admin`
- 密码：你在 `.env` 中设置的 `ADMIN_PASSWORD`

### 3. 首次登录后的操作

**强烈建议**：
1. 进入"设置" → "修改密码"，更改默认管理员密码
2. 创建一个 API Key（后面 Codex 会用到）

## 第五步：添加账户

现在你需要根据你有的服务类型添加账户。

### 情况 A：你有 Sub2API 服务

1. 点击左侧菜单 "账户管理"
2. 点击右上角 "添加账户"
3. 填写表单：
   - **Provider**: 选择 `sub2api`
   - **Name**: 自定义名称（如 "Sub2API Main"）
   - **Access Token**: 你的 Sub2API API Key
   - **Proxy URL**: 你的 Sub2API 服务地址（如 `https://api.sub2api.com`）
   - **Weight**: 10（默认）
   - **Concurrency Limit**: 5（可选）
4. 点击 "保存"

### 情况 B：你有其他服务（Claude/OpenAI/Gemini 等）

#### 如果有 Claude 账户：
1. Provider: `claude`
2. 需要通过 OAuth 方式添加（点击"添加账户"后按照提示操作）

#### 如果有 OpenAI 账户：
1. Provider: `openai`
2. Access Token: 你的 OpenAI API Key（`sk-proj-...` 格式）

#### 如果有 DeepSeek/Xiaomi/其他 API Key 类型：
1. Provider: 选择对应的 provider
2. Access Token: 你的 API Key
3. 不需要 Proxy URL

### 情况 C：我没有任何账户

如果你没有任何 AI 服务的账户，你需要：
1. 注册一个 AI 服务（Claude、OpenAI、DeepSeek 等）
2. 获取 API Key 或通过 OAuth 授权
3. 然后在 model-bridge 中添加账户

**推荐选择**（按性价比排序）：
- DeepSeek: https://platform.deepseek.com/ （国内可用，便宜）
- Claude: https://console.anthropic.com/
- OpenAI: https://platform.openai.com/

## 第六步：配置 Codex

### 1. 创建 API Key

在 model-bridge 管理面板：
1. 左侧菜单 → "API Keys"
2. 点击 "创建 API Key"
3. 填写：
   - **Name**: "Codex CLI"
   - **Allowed Providers**: 选择你添加的账户类型（如 `sub2api`）
   - 其他选项保持默认
4. 点击 "创建"
5. **重要**：复制生成的 API Key，只显示一次！

### 2. 安装 Codex CLI（如果还没有）

```powershell
# 使用 npm 全局安装
npm install -g @anthropic-ai/codex-cli

# 或使用 Homebrew（Mac/Linux）
brew install anthropic/tap/codex
```

### 3. 配置 Codex

```powershell
# 配置 Codex 连接到 model-bridge
codex config set baseURL http://localhost:3001
codex config set apiKey <你刚才复制的 API Key>

# 验证配置
codex config list
```

### 4. 测试连接

```powershell
# 简单测试
codex "你好"

# 如果成功，你应该看到 AI 的回复
```

## 第七步：验证 Sub2API 配置（如果使用 sub2api）

### 使用 curl 测试

```powershell
# 测试 /responses 端点（Codex 使用的端点）
curl -X POST http://localhost:3001/responses `
  -H "Authorization: Bearer <你的 model-bridge API Key>" `
  -H "Content-Type: application/json" `
  -d '{\"model\":\"claude-3-5-sonnet-20241022\",\"stream\":true,\"messages\":[{\"role\":\"user\",\"content\":\"test\"}]}'
```

**预期结果**：
- ✅ 成功：返回流式数据（SSE 格式）
- ❌ 失败：返回 503 错误

如果仍然失败，运行诊断：

```powershell
# 查看容器日志
docker-compose logs -f model-bridge

# 进入容器查询数据库
docker exec -it model-bridge-postgres psql -U model_bridge -d model_bridge -c "SELECT provider, name, status FROM accounts;"
```

## 常见问题和解决方案

### Q1: Docker Desktop 启动失败

**错误**：WSL 2 installation is incomplete

**解决**：
1. 以管理员身份运行 PowerShell
2. 运行：`wsl --install`
3. 重启电脑
4. 再次启动 Docker Desktop

### Q2: 端口被占用

**错误**：`Bind for 0.0.0.0:3001 failed: port is already allocated`

**解决**：
```powershell
# 查看占用端口的程序
netstat -ano | findstr :3001

# 修改 docker-compose.yml 中的端口映射
# 将 "3001:3000" 改为 "3002:3000"
```

### Q3: 数据库连接失败

**错误**：`FATAL: password authentication failed`

**解决**：
1. 确认 `.env` 文件中的 `PG_PASSWORD` 已设置
2. 删除旧的数据库卷：
   ```powershell
   docker-compose down -v
   docker-compose up -d
   ```

### Q4: 仍然报 "no sub2api account configured"

**解决**：
1. 登录管理面板 http://localhost:3001
2. 检查 "账户管理" 页面
3. 确认有 provider 为 `sub2api` 的账户且状态为 `active`
4. 检查账户的 `Proxy URL` 是否正确配置
5. 在 "API Keys" 页面，确认你的 Key 的 `Allowed Providers` 包含 `sub2api`

### Q5: Codex 配置后仍然报错

**检查 Codex 配置**：
```powershell
codex config list
```

确保：
- `baseURL` 是 `http://localhost:3001`（不是 3000）
- `apiKey` 是你在 model-bridge 创建的 Key
- 没有多余的 `/v1` 或其他路径后缀
