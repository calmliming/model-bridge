# 上游更新接入与修复

日期：2026-09-09。参考 Wei-Shaw/sub2api v0.2.3 及主线至 `270eac6973049fe1b50eb75560a74a029e82884c`，按 model-bridge 的 TypeScript 架构实现。

## MiniMax 接入

- 上游账户选择 MiniMax，填写平台 API Key。支持按量密钥及 Token Plan / Coding Plan 密钥；凭据使用现有加密存储。
- Base URL 留空使用 `https://api.minimaxi.com`；国际站填 `https://api.minimax.io`。支持根地址、`/v1`、`/anthropic` 和 `/anthropic/v1` 结尾。查询参数和 URL 片段不作为合法 SDK Base URL。
- 原生转发 Messages、Chat Completions、Responses；保留工具、图像输入、推理和缓存身份字段。Responses 同时支持 JSON 与 SSE。
- 本地前缀为 `/api/minimax/v1/messages`、`/api/minimax/v1/chat/completions`、`/api/minimax/v1/responses`、`/api/minimax/v1/models`。无服务商前缀的通用入口按 `MiniMax-*` 模型名路由。
- 模型目录包含 M3、M2.7、M2.7-highspeed、M2.5，模型广场新增 M3 和 M2.7。Key 服务商选项、账号批量导入和价格覆盖规则均支持 `minimax`。
- 连通性测试使用上游 `/v1/models`。配额刷新使用相同区域 API 主机的 `/v1/api/openplatform/coding_plan/remains`，只读取 `model_name=general` 的套餐窗口；不把视频额度用于文本账号停调。周窗口仅在 `current_weekly_status=1` 时有效。
- 配额刷新保存最后一次有效快照并检查停调阈值；失败不会覆盖旧快照。现有后台任务每分钟复核缓存快照，不自动轮询 MiniMax 额度接口。管理员可手动或批量刷新。

### 默认计价

采用核查当日 MiniMax 国际站公开美元价卡，每百万 token：M3 输入 0.30、输出 1.20、缓存读取 0.06；M2.7 同基础价格，缓存写入 0.375；M2.7-highspeed 输入 0.60、输出 2.40。M2.5 缓存读取为 0.03。

M3 总输入（含缓存）超过 512000 时输入与输出价格均乘 2。实际响应报告 `priority` 时再乘 1.5；不依据请求参数猜测实际服务层级。管理员可通过既有 `PRICING_OVERRIDE_FILE` 覆盖。MiniMax 图像输入按模型 token 计费，不走 GPT Image 专用价格。

## 分组模型白名单

分组新增 `allowedModels`：`null` 表示不限制，非空数组启用限制。创建和修改接口拒绝空数组；若数据库中出现显式空数组，网关按拒绝全部处理。

管理台新增开关及多行模型输入，支持不区分大小写的精确匹配和 `*` 通配符。限制同时用于模型发现、通用/服务商前缀转发、Gemini 路径模型、图片请求和 Responses 输入 token 预估。

按客户端原始模型名检查，检查失败返回 HTTP 404 和 `model_not_allowed`，且不获取账号或发起上游调用。模型映射不能用目标模型绕过原始名称限制；需要对外暴露的别名须在分组白名单中允许。原有 Key 限制独立生效。分组编辑后，现有 Key 下一次鉴权即读取新策略。

已有分组默认不受限制，不改变其调用范围。新增列通过启动初始化和幂等迁移 `0012_perpetual_wolfsbane.sql` 创建，迁移快照及 journal 同步更新。

## 稳定性修复

1. Codex 429 的 reset-only 响应头不再被当作账号额度耗尽证据。只有明确耗尽的窗口或错误体才能支持账号级判断；普通限流仍遵守 Retry-After。
2. 成功请求不再清除并发请求刚写入的冷却；失败更新不缩短既有冷却。两条路径均不会复活已停用账号。
3. 多个配额窗口同时达到阈值时，等待最后一个触发窗口重置，避免 5 小时窗口恢复后绕过仍触顶的周窗口。
4. 客户端断开会取消上游连接和读取，停止重试并释放账号、用户及 Key 并发槽。取消记录为 `client_disconnected`，保留已收到的用量，不据此惩罚账号或降低健康分。若断连发生在最终 usage 前，记录可能只有部分用量，未伪造完整账单。
5. 丢弃重试响应时先 abort 传输，再取消响应体，避免克隆流的一条分支等待另一条分支导致挂起。连接超时工具同时保留调用方信号和请求级取消信号。
6. 原生 Responses JSON 中的 failed/incomplete 不再仅因 HTTP 200 被记为成功，保留其已报告用量。
7. Grok Chat 移除上游不支持的 `external_web_access` 参数。

## 核查范围

Sub2API 的 Ollama Cloud 账号、Go Redis 连接池、HTTP/2 PING、代理备用链、Claude Code 专用客户端校验、插件 ZIP 安装和动态模型清单使用不同实现，本项目没有对应路径，未引入这些专属结构。OpenAI 满额周成本估算依赖其当前套餐窗口成本统计，本项目未提供同一数据口径，因此没有生成可能误导的估算值。

- 完整测试套件：591 项通过，数据库专项默认跳过；随后补充 Messages 计价字段、Base URL 校验和数据库策略读取测试，最终相关 58 项专项回归全部通过。
- 独立 PostgreSQL 16：4 项通过，覆盖初始化/迁移重复执行、旧结构缺列修复、分组部分更新、现有 Key 读取最新白名单、并发冷却、停用保护及健康分排除客户端取消。
- 前后端类型检查通过，前端生产构建通过。构建仍有既有 ECharts 大分块提示。
- 隔离页面验证：分组白名单保存与编辑回显、MiniMax 账号创建及配额/阈值入口正常；检查了两种表单的截图布局。
- 未使用生产凭据调用 MiniMax，协议和额度使用模拟响应验证；界面测试只使用无效占位密钥。未部署到生产环境。临时服务、数据库容器和测试启动脚本均已清理。
