# 动态目录与渠道健康实施说明

日期：2026-09-13。按本轮推荐顺序完成 Gemini 错误识别、动态模型目录和渠道健康看板。前一轮 Claude `output_config`、Codex `agent_message` 修复继续保留。

## 入口与使用

管理员侧边栏新增两个入口：

| 页面 | 地址 | 操作 |
| --- | --- | --- |
| 动态模型 | `/model-catalog` | 选择账号、手动同步、搜索模型，查看输入能力、上下文窗口及推理强度 |
| 渠道健康 | `/channel-health` | 切换时间、服务商、账号/模型维度、当前账号分组，查看 P95、错误分类和站内告警，保存告警阈值 |

这两项管理功能仅允许管理员访问。部署时按既有方式构建前端并重启后端，无需新增环境变量或数据库迁移；模型快照使用账号 metadata，告警阈值使用 settings 表。

## Gemini 错误识别

原生 Gemini、Sub2API Gemini 转接和 Antigravity 的原生 Gemini 输出路径，现在在 JSON/SSE 用量解析时同时识别响应结果：

- HTTP 200 内的 Google 错误信封记录为 `gemini_upstream_*`。
- 没有生成结果的空响应记录为 `gemini_empty_response`，保留已经报告的用量。
- `promptFeedback.blockReason` 和内容过滤类 `finishReason` 记录为 `gemini_policy_*`，排除在账号健康评分和渠道上游错误率之外。
- `STOP`、`MAX_TOKENS`、`OTHER`、`MALFORMED_FUNCTION_CALL` 等模型侧生成结果不自动归因于账号故障。
- `countTokens` 的正常响应仍可被识别，不会误报空生成结果。

客户端保留原生响应体与 HTTP 状态；统计状态由响应语义判断，不再只依赖 HTTP 200。流开始后不因这些信号重放请求或切号。请求流式响应但上游返回 JSON 时，按 JSON 处理，避免被当作 SSE 丢弃。持久化错误消息经过脱敏。

本轮没有重写 Antigravity 的 Gemini → Anthropic Messages 转换器；该转换器继续使用自身的完成/失败判断。

实现见 [结果识别](../src/providers/gemini/responseSignal.ts)、[用量解析](../src/providers/gemini/usage.ts)、[转发主流程](../src/routes/relay.ts)。

## 动态模型目录

支持 OpenAI、Sub2API、DeepSeek、小米、Qwen、智谱、Kimi、MiniMax 和 Grok 的目录同步。OpenAI 读取 Codex 模型接口，其余使用对应上游的模型列表接口。不同账号的接口支持和可用资格以上游实际响应为准；不支持的接口会显示同步失败并保留旧结果。

- 后台每分钟检查待更新账号；同一账号每 6 小时尝试一次，每轮最多处理 10 个，避免集中请求上游。手动同步不必等待周期。
- 同账号并发同步合并为一个请求；读取限制为 15 秒、2 MB 和 2000 个原始条目。
- 只保存模型 ID、显示名、输入模态、上下文/最大上下文窗口、推理强度等允许字段，不保存上游任意附加字段。
- 同步失败不覆盖最近有效快照；停用账号不参与目录查询。修改账号来源后，旧来源快照失效。
- 客户端目录按当前 Key 所属账号池查询，再执行服务商限制、Key 模型限制、分组白名单和模型映射规则。
- 账号池中尚有未同步账号时保留静态目录回退，并纳入已发现的新模型 ID；此时不宣称所有账号共享同一能力。
- 同模型在多个已同步账号间出现能力差异时，采用共有输入模态、推理强度和较小窗口；能力字段缺失时保留“未提供”语义。

原有 OpenAI 风格 `/v1/models` 列表现在可携带动态能力字段；新增 `/v1/models/:model`、`/models/:model` 及对应服务商前缀的单模型查询。不可见模型返回 404，单模型接口与列表使用同一套权限过滤。

本轮保持原有 OpenAI 风格模型列表协议，未合成 Codex 专用完整 manifest，也未保证客户端自动出现 Fast/Speed 选择器。模型可见不代表账号一定可调用，目录同步也不会自动修改定价。

实现见 [账号同步与缓存](../src/accounts/modelCatalog.ts)、[目录字段规范化](../src/providers/modelCatalog.ts)、[客户端目录](../src/providers/modelDiscovery.ts)、[管理页面](../web/src/views/ModelCatalogView.vue)。

## 渠道健康与站内告警

看板直接聚合已有 `usage_logs`，范围为最近 1–168 小时，提供：

- 服务商、账号、模型三个查看维度，以及服务商和当前账号分组筛选。
- 请求量、有效样本、上游失败数、错误率、成功请求的首 Token P95 和总耗时 P95、小时趋势。
- 客户端取消、内容策略拒绝和明确的参数错误单独计数，不进入上游错误率分母。
- 样本不足显示“样本不足”；没有延迟样本显示 `—`，不当作 0 毫秒或已验证正常。
- 默认告警条件：至少 20 个有效样本，上游错误率达到 10%；或者至少 20 个成功延迟样本且首 Token P95 达到 10000 ms。管理员可调整并保存。
- 站内告警随当前统计窗口和阈值计算，恢复后自动消失；未新增邮件、短信或外部消息推送，也未建立历史告警事件工单。

分组筛选按账号当前归属选择历史请求，不表示请求发生当时的分组快照。跨多个组的账号通过 EXISTS 筛选，不会重复计数。明细上限为 500 项；超限显示提示，此时顶部卡片汇总所展示明细，小时趋势仍覆盖完整筛选结果。

首 Token 延迟复用本项目已有 `first_token_ms` 记录口径。历史缺失字段不会补造，旧日志也不回写新的错误分类。

实现见 [统计与阈值](../src/usage/channelHealth.ts)、[管理接口](../src/routes/operations.ts)、[健康页面](../web/src/views/ChannelHealthView.vue)。
