# 套餐对标 OpenCode Go

## 已确认的范围

用户选择保留 Lite / Pro / Max 的 10 / 30 / 100 美元月费，参考 Go 的用量规则。Pro 和 Max 是本站按 Go 基准放大的三档设计，不是 OpenCode 的官方套餐名称或 Go Plus 额度。

2026-09-29 核对 [OpenCode 当前 Go 文档](https://opencode.ai/docs/go/#usage-limits)：Go 月费 10 美元，不同模型的月参考用量分为 60、30、15 美元，五小时和周窗口分别占月额度的 20% 和 50%。当前还存在 40 美元的 Go Plus，其模型额度并非统一按 Go 四倍增加，本次不套用 Go Plus。

## 本站三档额度

| 套餐 | 月费 | 五小时点数 | 周点数 | 月点数 |
| --- | ---: | ---: | ---: | ---: |
| Lite | $10 | 12,000 | 30,000 | 60,000 |
| Pro | $30 | 36,000 | 90,000 | 180,000 |
| Max | $100 | 120,000 | 300,000 | 600,000 |

三档在相同模型上的容量为 1 / 3 / 10 倍，单位价格相同，不额外虚构高档优惠。窗口的重置方式沿用项目既有规则：首次消耗开始五小时会话、订阅开始日锚定周窗口、实际付费账期或日历月作为月窗口。

## 模型权重与共享额度

每次基础点数仍来自本项目价目表和上游返回的实际 Token 用量，然后按模型乘以 1、2、4。倍率不会修改钱包按量计费价格，也不会添加此前未接入的模型。

| 扣点倍率 | 示例 | Lite 月参考用量 | Pro 月参考用量 | Max 月参考用量 |
| --- | --- | ---: | ---: | ---: |
| 1 倍 | DeepSeek V4.1 Flash、MiniMax M3、Kimi K2.7 Code | $60 | $180 | $600 |
| 2 倍 | DeepSeek V4 Flash 旧型号、Qwen3.8 Flash | $30 | $90 | $300 |
| 4 倍 | Kimi K3、Grok 4.7、GPT 6 Luna | $15 | $45 | $150 |

未列入当前 Go 基准名单的模型，本站默认使用 4 倍扣点。这是本站扩展规则，不代表 OpenCode 提供 Claude 等未列出的模型，也不代表它们具有相同的采购成本。后续可在后台将套餐切换回原始统一权重方案，或按实际成本调整三项额度。

本项目将 deepseek-flash / deepseek-chat / deepseek-reasoner 视为当前 Flash 别名，按 V4.1 Flash 的 1 倍规则处理；显式的 deepseek-v4-flash 按旧型号 2 倍处理，视觉实验版本优先按 4 倍处理。具体型号匹配规则保存在 src/subscriptions/usageProfiles.ts。

不同模型不会各自得到一份完整额度。例如 Lite 使用 1 美元的标准模型参考用量，再使用 1 美元的 4 倍模型参考用量，共消耗 5,000 点，占月额度的约 8.33%。同一个订阅内的多个 API Key 仍共享计数。

点数不是可兑换余额。参考金额是本站模型价目表的计算结果，未直接复制 OpenCode 全部 Token 单价；如果两边价目表不同，同样金额额度并不保证相同 Token 数或请求数。缓存和模型差异保留，微小用量的精度修复继续生效。

## 前后台与账单

- 套餐卡片显示真实点数，并可展开“不同模型能用多少”查看三档参考用量。
- 管理后台可以选择“统一模型价卡加权（原规则）”或“参考 Go”。切换规则不自动更改三项上限。
- 每次结算在数据库事务内读取规则、应用倍率、更新共享窗口；流水保存实际扣点和当次倍率，便于核对。
- 任一窗口耗尽后仍暂停新请求，返回原有 429。本次没有实现 OpenCode 的可选“超额使用钱包余额”功能，也不会自动转扣钱包。

## 升级与部署

新增 usage_profile 字段，默认 base，保持已有套餐的原计量规则。迁移 SQL 0019 和启动初始化均可重复执行，Drizzle 元数据已同步。

一次性默认套餐升级只处理名称、价格、旧额度完全匹配、没有订阅和结账记录的内置套餐。已售、待付款和自定义套餐保留原规则；启动重复执行不会覆盖后续手动修改。旧版金额套餐仍按原有逻辑运行。

本地三档已升级。线上代码、数据库和 Waffo 产品未由本次任务发布或修改。套餐售价、Waffo 产品 ID 与原先相同。

## 成本与价格口径

这是用户指定的竞品用量目标，不是已经由采购账单证明的利润模型。混合上游仍需分别核算包月账号池容量与按量 API 进价。比较套餐和按量购买时需要使用相同的实付款币种、充值换算和分组倍率；沙箱里“1 元 = 1 USD 站内余额”的测试比例不能直接当作正式美元月费的比较基准。
