# model-bridge 与 sub2api 功能差距对比

核查日期：2026-09-12。

- 本地基线：model-bridge `0.2.0`，HEAD `c0bb883`，加上本会话尚未提交的 Claude `output_config` 和 Codex `agent_message` 兼容修复。
- 上游正式版：[Sub2API v0.2.4](https://github.com/Wei-Shaw/sub2api/releases/tag/v0.2.4)，2026-09-09 发布。
- 上游主线：[`bdb42e22f81fcb633ff0a060961211dd2bcb515b`](https://github.com/Wei-Shaw/sub2api/tree/bdb42e22f81fcb633ff0a060961211dd2bcb515b)，相对 v0.2.4 多 142 个提交，包含合并提交。下文标注“主线”的能力不代表已进入正式版。
- 方法：检查本地路由、数据结构、转发器、管理界面和上游对应代码。能力存在不表示两边在性能、可用性或所有协议边界上完全等价；本轮没有生产环境测试。

## 结论

model-bridge 已覆盖主要中转、账号管理与收费流程。sub2api 的主要增量集中在模型能力发现、渠道运维、安全认证、细粒度运营策略和更多媒体/上游接口。新增功能应按本项目实际使用场景选择，不需要以版本号相同或复制全部菜单为目标。

旧文档 `comparison-with-sub2api.zh-CN.md` 的表格已明显滞后。本文件作为本次核查快照，优先于旧表中关于“尚未接入”的判断；旧文档保留作历史记录。

## 保持独立跟踪的兼容修复

1. **Gemini HTTP 200 内的错误识别**：本地原生 Gemini 仍可能将响应体错误记为成功；需要把错误信封、空响应、内容策略结果和正常模型停止分开处理。参考 [上游 PR #6929](https://github.com/Wei-Shaw/sub2api/pull/6929)。这属于已有接口正确性修复，可先于新的渠道健康统计完成。
2. **Codex 出站身份维护**：本地 `src/providers/openai/constants.ts` 仍固定为 `codex_cli_rs/0.20.0`。上游已有[版本同步服务](https://github.com/Wei-Shaw/sub2api/blob/bdb42e22f81fcb633ff0a060961211dd2bcb515b/backend/internal/service/openai_codex_version_sync_service.go)。后续应核查当前真实协议要求和本项目所有出站路径，再设计可配置版本、缓存和回退；不能仅凭版本号较老就断言现网不可用。
3. **流式记账失败恢复**：本地 `src/usage/recorder.ts` 写入失败后记录错误并返回 false；未发现持久化补记队列。它是本地后续可靠性候选，不应把“等待在途写入”描述成失败恢复或持久化保证。本次不据此宣称 sub2api 已实现完全对应的机制。

## 实施顺序建议

以目前代码和中转用途为前提，建议下一轮先修 Gemini 错误归类，再新增动态模型目录和渠道健康看板。需要新生图能力时，将 Image 2.5 提升为第一项；需要 Zen/Go 上游时再安排 OpenCode 接入。公开运营场景可优先加入 TOTP 与操作审计，然后扩展分平台限额和利润策略。

本轮只新增对比文档，未修改业务代码或执行部署。前一轮兼容修复仍保留在工作区；其 105 项相关测试与类型检查结果见修复记录，本次未重复运行测试。
