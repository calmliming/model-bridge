# Gemini 授权启动错误修复说明

## 已确认的原因

请求为 `POST /api/admin/accounts/oauth/start`，参数为 `{"provider":"gemini","name":"gemini-01"}`。线上响应明确提示 `GEMINI_OAUTH_CLIENT_ID / GEMINI_OAUTH_CLIENT_SECRET must be set`，说明服务进程未读到 Gemini 上游授权所需的完整客户端配置。

网站登录的 `GOOGLE_LOGIN_CLIENT_ID` 与这里的 Gemini CLI OAuth 配置用途不同。生成授权链接这一步只做本地参数构造和授权会话入库，不会向 Google 发起请求，因此当前报错不是 Google 网络出口或回调端口导致的。

排查时已发布版本的 Docker Compose 文件没有向 `model-bridge` 服务传入这两项变量。即使写入项目 `.env`，Compose 也需要在服务的 `environment` 中显式引用，应用容器才能读取。

## 线上配置步骤

1. 在服务器项目根目录 `.env` 中设置 Gemini CLI 对应的客户端参数：

   ```dotenv
   GEMINI_OAUTH_CLIENT_ID=填入对应的客户端ID
   GEMINI_OAUTH_CLIENT_SECRET=填入同一客户端对应的secret
   ```

   项目这条接入路径使用 Gemini CLI 安装应用的 OAuth 客户端。对应值可核对 [Gemini CLI 官方源码中的 OAUTH_CLIENT_ID 与 OAUTH_CLIENT_SECRET](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/code_assist/oauth2.ts)。官方源码明确说明这是一组随安装应用公开分发的客户端标识。不要将网站 Google 登录的 Web 客户端配置混入这两个变量。

2. 确认 `docker-compose.yml` 的 `services.model-bridge.environment` 中有：

   ```yaml
   GEMINI_OAUTH_CLIENT_ID: ${GEMINI_OAUTH_CLIENT_ID:-}
   GEMINI_OAUTH_CLIENT_SECRET: ${GEMINI_OAUTH_CLIENT_SECRET:-}
   ```

3. 重新创建应用容器，使环境变量进入服务进程：

   ```sh
   docker compose up -d --force-recreate model-bridge
   ```

   如果同时部署此次代码修复，则使用：

   ```sh
   docker compose up -d --build --force-recreate model-bridge
   ```

4. 只检查是否配置，不输出实际值：

   ```sh
   docker compose exec -T model-bridge node -e 'for (const name of ["GEMINI_OAUTH_CLIENT_ID","GEMINI_OAUTH_CLIENT_SECRET"]) console.log(name+": "+(process.env[name]?.trim()?"已配置":"缺失"))'
   ```

5. 两项都显示“已配置”后，重新在后台添加 Gemini 账号并生成授权链接。配置正确时该启动接口应返回 `state`、`authorizeUrl` 和 `mode`；后续 Google 账号授权及令牌交换另行完成。

直接运行 Node 服务时，设置运行该服务的环境变量或根目录 `.env` 后重启进程即可。

## 代码修复

- Gemini 缺少配置时抛出专用配置错误；接口返回 `503 / oauth_not_configured`、缺失的变量名以及中文修复提示，不再抛出笼统的 500。
- 先构造和校验授权链接，再写入授权会话，避免缺少配置时留下不可用的会话。
- 授权会话存储错误返回 `503 / oauth_session_unavailable` 与请求编号；日志只记录安全的数据库错误码，不暴露 SQL 参数或 PKCE verifier。
- 授权启动响应设置 `Cache-Control: no-store`。
- Docker Compose 显式传入 Gemini 两项变量，配置示例明确区分 Gemini 上游授权与网站 Google 登录。

## 验证结果与范围

修复前通过接口测试复现配置缺失产生的 500。独立提交版本的 24 项相关测试通过，覆盖 Gemini 配置缺失、仅配置网站登录、缺少 secret、成功生成授权链接、其他 OAuth 服务商、数据库失败和管理员鉴权；TypeScript 类型检查通过。Docker Compose 使用测试值校验了两个变量确实进入应用服务配置。

此次代码改动在本地工作区完成；线上容器的环境变量尚需按上述步骤配置，未进行真实 Google 账号授权或生产服务重启。
