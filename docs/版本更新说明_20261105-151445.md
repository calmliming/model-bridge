# Model Bridge 0.3.0 更新说明

本版本落地 Sub2API 跟进清单 F01–F24 在本项目中的适配：修复模型计费与协议兼容，增加上传和响应的资源限制，补齐生图调度、受限管理凭证、只读 OAuth MCP 与注册邮箱黑名单。后端、前端 package.json 及两个锁文件统一为 0.3.0，控制台版本徽标和 MCP serverInfo 使用项目版本。

| 范围 | 新行为 |

## 管理入口

管理员在系统设置点击“管理访问与策略”，或访问 `/management`，可以创建、轮换、撤销管理 Key，配置账号生图尺寸、分组图片计费、邮箱名单，并查看操作审计。用户可从个人概览进入 `/app/mcp`；管理员可从管理页进入 `/mcp/authorize`。

### 受限管理员 Key

完整 Key 只在创建或轮换时展示，数据库保存不可逆摘要。支持指定操作、账号 ID、分组 ID、过期时间和 IP/CIDR。

- 账号与分组范围同时填写时，要求同一个账号同时满足两个范围。空范围表示不限制该维度，空数组表示没有匹配资源。
- 用户资料读取、审计读取是单独授予的全站权限；仅授予 accounts.read 不会获得这些权限。
- 模型调用 Key、管理 Key、浏览器登录会话和 MCP OAuth 令牌分别认证。
- 导入和额度重置必须携带 Idempotency-Key。相同身份、参数和策略的重试复用已完成结果；冲突或结果不确定时返回 409，避免重复执行上游操作。
- 密码修改后撤销旧管理员会话；多实例的会话版本最多约一秒传播，版本存储持续不可用时校验失败关闭。
- 机器额度查询仅使用已有有效凭据；需要凭据恢复时返回 409。仅有重置权限的响应只确认结果，读取额度快照须另外授予 accounts.quota.read。

机器接口以 `/api/management` 为前缀：

| 接口 | 所需权限 |
| --- | --- |
| GET /accounts | accounts.read |
| PATCH /accounts/:id/status | accounts.status.write |
| POST /accounts/:id/quota/read | accounts.quota.read |
| POST /accounts/:id/quota/reset | accounts.quota.reset |
| POST /accounts/import | accounts.import |
| GET /groups | groups.read |
| GET /users | users.read |
| GET /usage | usage.read |
| GET /audit | audit.read |

查询示例：

```sh
curl 'https://bridge.example/api/management/accounts?page=1&pageSize=25' \
  -H 'x-admin-api-key: <MANAGEMENT_KEY>'
```

导入示例；以下为占位符：

```sh
curl 'https://bridge.example/api/management/accounts/import' \
  -H 'x-admin-api-key: <MANAGEMENT_KEY>' \
  -H 'Idempotency-Key: import-development-account-001' \
  -H 'Content-Type: application/json' \
  -d '{"name":"开发账号","provider":"openai","accessToken":"<TOKEN>","refreshToken":"<REFRESH_TOKEN>","chatgptAccountId":"<CHATGPT_ACCOUNT_ID>","groupIds":["<GROUP_ID>"]}'
```

管理 Key 创建、轮换和撤销仍通过管理员浏览器会话执行。操作审计记录身份、操作、资源 ID、状态和时间，不保存密钥或完整请求体。导入使用独立接口的字段白名单。

### OAuth MCP

MCP 默认关闭；配置可信的公开资源地址后重启：

```dotenv
MCP_PUBLIC_URL=https://bridge.example/api/mcp
# 前后端分域部署时填写平台授权页面所在前端：
MCP_FRONTEND_URL=https://console.example
```

资源路径必须为 `/api/mcp`。生产使用 HTTPS，回环地址可用 HTTP。反向代理转发 `/api/mcp`、`/api/mcp/oauth/*` 和 `/.well-known/oauth-*`；前端提供 `/mcp/authorize` 页面。服务不根据请求 Host 推断公开地址。带 Origin 的请求只接受资源站点和已配置的平台前端；浏览器客户端需经这些受信入口调用。

客户端配置示例：

```json
{
  "mcpServers": {
    "model-bridge": { "url": "https://bridge.example/api/mcp" }
  }
}
```

采用无状态 Streamable HTTP JSON 响应、OAuth 授权码及 S256 PKCE，包含资源绑定、动态客户端注册、授权码重放防护、短期访问令牌和刷新令牌轮换。访问令牌为十分钟；授权最长三十天。重复使用已消费授权码或刷新令牌会持久撤销该授权。每个用户最多二十个有效授权，可在页面撤销；账号停用会持久撤销，重新启用不会恢复旧授权。

本版提供个人只读工具：资料与余额、用量记录、Key 元数据和订阅。管理员可以明确选择平台只读范围，额外查询上游账号状态和全站用量。工具结果不会返回模型密钥、上游凭据或密码。工具参数封闭且分页有上限，拒绝 JSON-RPC 批量请求；每次工具查询记录审计。协议实现依据 [MCP 授权规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)和 [Streamable HTTP 规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)。

## 生图与运营策略

### 尺寸与上传

管理页可对一个或多个 OpenAI 账号配置 1K/2K/4K 档位。最长边不超过 1024 为 1K，不超过 2048 为 2K，其余为 4K；配置留空表示不限。已知尺寸硬过滤；auto/缺失尺寸保留粘性绑定，并优先选择不限或支持更大尺寸的账号。整个分组没有所需能力时返回 400，临时冷却或忙碌仍返回 503。

图片 multipart 单文件上限提高至 50 MiB，专用图片端点总包上限为 128 MiB；实际还受实例内存预算约束。64 MiB 的多模态端点限制保留。需要大图片时，应一起核对上传、预读、SSE 和非流式缓冲上限，不能只提高其中一项。

### 分组计费

专用 OpenAI 图片端点支持三种分组策略：tokens 仅按 Token、per_image 按最终实际图片张数、both 为 Token 加已配置的每张费用。存量分组默认 both，保留原有语义。per_image 未配置每张价格时仍按 Token 结算，避免无价格配置导致免费生成。Responses 内的图片工具继续按原 Token 规则计费。

运营定价规则通过已有的 PRICING_OVERRIDE_FILE 配置。为模型添加 imageRequest 时保留其 Token 价格；按张分组会选择按张费用。例：

```json
{
  "version": 1,
  "rules": [{
    "provider": "openai",
    "model": "gpt-image-2",
    "price": {
      "input": 5, "output": 10, "cacheWrite": 0, "cacheRead": 1.25,
      "imageInput": 8, "imageOutput": 30,
      "imageRequest": 0.10
    }
  }]
}
```

imageRequest 是运营者明确配置的每张销售价，示例不代表上游公布的按张价格。both 模式会同时收取 Token 和每张费用；如只希望按张收费，应将对应分组设为 per_image。

### 注册邮箱

名单最多二万条。Gmail/googlemail 的点号和加号别名按同一收件箱匹配，其他域名不擅自删除本地部分字符。校验覆盖注册发码、验证码确认和 Google 首次建号；已存在用户的登录仍由用户状态控制。

保存名单与停用历史用户为两步：先保存，再检查并预览最多一千个仍启用的命中用户，明确确认后批量停用。管理员关联用户受保护；停用同时撤销 MCP 授权。名单按进程缓存，其他副本最多约六十秒生效。

## 默认资源参数

参数已列入仓库 `.env.example`。内存预算为保守的对象存储估算，包含字符串/规范化副本的倍率，不等同于进程 RSS；部署时为运行时、数据库驱动及其他服务留出空间。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| INGRESS_MEMORY_MAX_BYTES | 256 MiB | 实例上传及请求体保留预算 |
| UPSTREAM_MEMORY_MAX_BYTES | 256 MiB | 实例上游缓冲峰值预算，保留至处理结束 |
| SSE_EVENT_MAX_BYTES | 64 MiB | 单 SSE 行/事件上限 |
| SSE_EVENT_MAX_LINES | 4096 | 单事件行数上限，包含注释与多行 data |
| STREAM_PEEK_MAX_BYTES | 4 MiB | 首包预读/重放上限 |
| UPSTREAM_BUFFER_MAX_BYTES | 64 MiB | 非流式全文及转换器保留上限 |
| UPLOAD_TIMEOUT_MS | 120000 | 上传读取期限 |
| UPSTREAM_IDLE_TIMEOUT_MS | 180000 | 上游相邻读取的空闲期限 |
| STREAM_DRAIN_TIMEOUT_MS | 3000 | 已开始响应后，下游断开的总尾包等待预算；0 为立即取消 |
| USAGE_WRITE_CONCURRENCY | 8 | 结算执行并发 |
| USAGE_WRITE_QUEUE_MAX | 256 | 结算等待队列上限 |
| DB_STATEMENT_TIMEOUT_MS | 30000 | SQL 语句期限 |
| CN_RATE_LIMIT_COOLDOWN_MS | 5000 | 明确瞬时频率限制的兜底冷却；0 关闭 |
| CN_QUOTA_EXHAUSTED_COOLDOWN_MS | 1800000 | 明确余额/套餐耗尽的兜底冷却 |
| GEMINI_SAME_ACCOUNT_RETRIES | 4 | Gemini 同账号额外重试上限，范围 0–10 |

有效 Retry-After 或重置时间优先。健康流没有统一的短时总寿命限制；排空预算不会因心跳续期。上传/响应容量不足返回相应错误并回收资源，流式错误通过协议事件结束，不伪造成功。计费写入拥塞时保留持久化重放，幂等结算避免重复扣款。

## 升级和验证

启动时通过现有 initDb 流程自动创建管理 Key、审计、幂等及 MCP 授权表，并为分组增加 image_billing_mode。已有模型价保留人工覆盖，新增模型只补缺失条目。无需手工执行 SQL；按常规部署流程先备份数据库并构建新镜像。

管理员登录接口新签发的会话包含版本号。修改密码会撤销旧会话；角色缺失的 JWT 不再作为管理员凭证接受。MCP 保持关闭，直到部署方配置公开资源地址。

验证结果：

- 158 个测试文件、1938 项全量测试通过，含本机独立 PostgreSQL 容器和各测试独立 schema 的数据库回归。
- 随后的 Antigravity 身份前导和模型展示边界定向回归通过；新增 Codex 冷缓存并发隔离测试通过，followups.test.ts 当前 23 项通过。
- 后端 TypeScript、前端 vue-tsc 检查和前端生产构建通过；npm ci 成功，锁文件解析 follow-redirects 为 1.16.2。
- 数据库用例覆盖资源范围、只读拒写、过期/IP、轮换/撤销、PKCE、资源/回调绑定、OAuth 重放、用户停用及恢复、管理写入幂等和黑名单管理员保护。
- 没有真实付费模型调用、上游额度重置、支付操作或生产数据库变更。MCP 通过协议和数据库集成用例验证，尚未以用户的真实第三方客户端账号进行连接验收。

Windows 保留文件同步和原子重命名，目录 fsync 因平台不支持而跳过；POSIX 的目录同步继续保留。Windows 的 NTFS ACL 与 POSIX mode 位不同，相关测试按平台验证，不能把 POSIX 权限位直接当作 Windows ACL。
