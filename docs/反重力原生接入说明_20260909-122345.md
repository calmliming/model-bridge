# 反重力原生接入说明

日期：2026-09-09。当前未发布版本：`0.2.0`。

## 已实现的调用链

客户端 → model-bridge → Google Antigravity。

新增独立服务商 `antigravity`，直接处理 Google OAuth、令牌刷新、项目初始化、模型/配额查询和生成请求，不依赖 Sub2API。此前的 Sub2API 转接方式保留，两个服务商分别配置、调度和记账。

本轮提供 Anthropic Messages 和 Gemini 原生协议，支持 JSON 与 SSE。Messages 支持文本、base64 图片/文档输入、函数工具及工具结果、多轮思考签名；Gemini 原生接口保留完整 Gemini 内容结构。Messages 的 Responses / Chat Completions 转换不在本轮范围内。

## 服务器配置

在服务器 `.env` 配置与 Antigravity 桌面 OAuth 客户端匹配的参数：

```dotenv
# 已内置此公开客户端 ID，可按需要覆盖。
ANTIGRAVITY_OAUTH_CLIENT_ID=1071006060591-tmhssin2h21lcre235vtolojh4g403ep.apps.googleusercontent.com
ANTIGRAVITY_OAUTH_CLIENT_SECRET=填写匹配的桌面客户端参数
ANTIGRAVITY_USER_AGENT_VERSION=2.12.2
ANTIGRAVITY_API_HOST=daily-cloudcode-pa.googleapis.com
ANTIGRAVITY_PROXY_URL=
```

客户端参数属于 OAuth 应用配置，不是 Google 账号密码，也不是用户 refresh token。本项目没有写入真实用户凭据或内置用户令牌；client secret 沿用环境变量配置方式。公开兼容实现的参数位置见文末参考资料。

`ANTIGRAVITY_API_HOST` 允许 `daily-cloudcode-pa.googleapis.com` 或 `cloudcode-pa.googleapis.com`。项目/配额初始化使用生产管理端点，生成使用所选端点。User-Agent 版本可随 Google 要求更新；当前默认依据核查当日官方应用版本设置。

如需要固定网络出口，可配置 HTTP、HTTPS 或 SOCKS5 代理，例如 Docker 访问宿主机代理：

```dotenv
ANTIGRAVITY_PROXY_URL=http://host.docker.internal:7890
```

该设置用于本项目所有原生 Antigravity 账号的 OAuth、刷新、项目/配额查询及生成请求；本轮没有增加逐账号代理配置。它是网络代理，不是账户中的 Sub2API Base URL。固定 Google 上游域名、HTTPS 校验及重定向保护继续生效。

Docker Compose 已透传以上环境变量。修改后重新构建并重启应用，或在本地启动服务。

## 账号授权

1. 进入「上游账户 → 添加账户」，选择 **Antigravity（反重力）**。
2. 填写名称，生成授权链接，用符合 Antigravity 使用资格的 Google 账号登录并授权。
3. 回调使用 `http://localhost:8085/callback`。本地运行时可自动完成；远程或 Docker 部署时，可从浏览器地址栏复制完整回调 URL，粘贴回管理台完成，不要求从公网开放该回调端口。
4. 授权成功后点击「刷新配额」，重新查询项目、套餐标识、模型目录和每个模型的剩余额度。
5. 给原生 Antigravity 账号建立独立分组，创建本地 Key，服务商限制选择 `antigravity` 并绑定同一分组。

授权会话包含 state 和 PKCE，有效期 30 分钟，回调/手动完成均一次性消费。后台令牌刷新使用独立 Antigravity OAuth 配置，保留未轮换的 refresh token。需要 onboarding 时只使用 Google 返回的默认 tier，不编造项目或套餐资格。

现有 Token 导入也接受 `provider: "antigravity"`，导入时查询项目。若未提供到期时间，访问令牌默认按 1 小时处理；长期使用应包含有效 refresh token。账户列表可查看令牌刷新时间。

## 客户端地址

| 用途 | 路径 |
| --- | --- |
| Messages | `/api/antigravity/v1/messages` |
| Messages 输入 token 预估 | `/api/antigravity/v1/messages/count_tokens` |
| OpenAI 格式模型目录 | `/api/antigravity/v1/models` |
| Gemini JSON | `/api/antigravity/v1beta/models/{model}:generateContent` |
| Gemini SSE | `/api/antigravity/v1beta/models/{model}:streamGenerateContent` |
| Gemini 模型目录/详情 | `/api/antigravity/v1beta/models`、`/api/antigravity/v1beta/models/{model}` |

Claude Code 示例：

```bash
export ANTHROPIC_BASE_URL=https://你的-model-bridge/api/antigravity
export ANTHROPIC_AUTH_TOKEN=mb-本项目生成的密钥
claude --model 账号实际支持的模型名
```

Gemini SDK 使用 `https://你的-model-bridge/api/antigravity` 作为服务 Base URL，最终路径与上表一致。模型名使用配额刷新后查询到的实际名称，支持 Gemini 和 Claude 模型家族。

仅允许 `antigravity` 的 Key 也可通过通用 `/v1/messages`、`/v1/messages/count_tokens` 和 `/v1beta/models/*` 入口访问原生池。服务商混合 Key 使用显式 `/api/antigravity` 前缀选择原生池。

模型目录按同一账号分组读取有效账号的缓存，并应用 Key/分组白名单。尚未刷新目录时可回退到内置候选列表；内置候选不代表该账号已获模型权限。

## 签名、工具和用量

- Gemini `thoughtSignature` 与 Messages `thinking.signature` 按协议转换并保留。不伪造签名；缺少必需签名的思考历史返回客户端错误，切换服务商应新开会话。
- 工具签名补充缓存按 Key、账号、模型及会话标识隔离，避免跨会话复用同名调用的签名。缓存限量 5000 条/16 MiB、有效期 30 分钟，属于进程内兼容缓存；重启或跨实例续聊时，客户端仍应完整传回签名，必要时新开会话。
- 函数参数保留结构，本地 schema 引用先展开再规范化。无法支持的块、外链媒体、混合内置搜索与函数工具会明确拒绝，不静默删除请求能力或切换模型。
- Messages 输出上限限制为 64000，思考预算保持小于输出上限；Gemini 3.8 的配置按现有兼容规则规范化。
- Gemini 思考 token 计入输出总量，缓存读取从总输入拆分；在本项目按所选 Claude/Gemini 模型的既有价格策略记账。`PRICING_OVERRIDE_FILE` 支持 `provider: "antigravity"`。
- Messages token 预检是本地近似值，响应含 `x-model-bridge-token-estimate: approximate`；不请求 Google，也不用于最终费用结算。
- 模型额度触顶仅暂停相应模型。并发模型冷却原子合并，不覆盖其他模型或项目/套餐元数据；过期条目清理且不缩短既有停调时间。
- 客户端断开停止上游读取并释放并发槽；流式缺少完成事件会记为失败，不伪造成功结果。

## 验证及运行边界

全量 645 项测试通过，独立 PostgreSQL 16 的 6 项回归通过；随后追加会话签名隔离和 token 预检，相关专项回归通过。前后端类型检查、前端生产构建和差异格式检查通过。

模拟上游加真实 loopback HTTP 覆盖了原生 Messages/Gemini、JSON/SSE、工具调用、签名隔离、终止事件、计费和分组目录。独立数据库验证了并发冷却合并、目录分组隔离、迁移兼容和停用保护。管理台验证了原生服务商选择、授权链接、8085 回调提示、按模型额度展开及 v0.2.0 显示。

没有使用真实 Google 账号登录、授权或调用模型，也没有部署到生产。实际调用仍取决于 Google 账号资格、地区、可用模型和网络出口。兼容协议并非 Google 承诺稳定的公共 API；官方 FAQ 当前不支持第三方软件复用 Antigravity 登录。配置代理无法改变账号本身的资格。
