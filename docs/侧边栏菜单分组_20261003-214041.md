# 侧边栏菜单分组说明

## 改动目标

管理端侧边栏原有 16 个菜单项平铺在一个「管理」标题下，项目多、层级不分，找功能要逐条扫。本次只调整**排列顺序与分组**，不改任何页面的路由、路径和功能。

## 管理端分组

侧边栏改为 8 个分组，顺序即展示顺序：

| 分组 | 菜单项 |
| --- | --- |
| 概览 | 仪表盘、模型广场 |
| 服务与模型 | 动态模型、渠道健康 |
| 账号与调度 | 上游账户、分组管理 |
| 访问与用户 | API Keys、用户钱包 |
| 计费与套餐 | 充值订单、兑换码、订阅套餐 |
| 数据分析 | 调用日志、用量统计 |
| 文档与支持 | 使用文档、API 文档 |
| 系统 | 设置 |

分组依据是「谁和谁一起用」：先看板，再上游资源与账号调度，然后是面向终端用户的访问与计费，最后是分析、帮助和系统设置。原来的顺序把「调用日志」夹在「渠道健康」和「上游账户」之间、「模型广场」与「动态模型」相邻但职责不同，现在按用途归位。

## 用户端分组

用户中心原 6 项平铺，改为 3 组：

| 分组 | 菜单项 |
| --- | --- |
| 总览 | 概览、模型广场 |
| 接入与用量 | API Keys、用量流水、调用日志 |
| 帮助与文档 | API 文档 |

## 实现要点

- 两个布局的菜单从一维数组 `menu` 改为分组数组 `menuGroups`（`{ id, label, items }`），渲染改为两层 `v-for`，组内项的样式、图标、高亮标记逻辑保持不变。
- 分组标题用 `role="group"` + `aria-labelledby` 关联，键盘与读屏软件能识别分组边界。
- 侧边栏收起时分组标题隐藏（`lg:hidden`），组间距由 `space-y-5` 收紧为 `space-y-3`，避免收起后出现空档。
- 顺带修复：用户端「API 文档」原 `key` 为 `user-api-docs`，但 `/docs/api` 的路由名是 `api-docs`，高亮态按 `route.name` 匹配，导致用户端进入 API 文档页时菜单不高亮。现统一为 `api-docs`，`titleMap` / `subtitleMap` 同步更新。

## 验证

- 全量回归：123 个测试文件通过、7 个跳过，1302 项测试通过。
- `npm run typecheck`（后端 tsc）与 `web` 目录 `vue-tsc --noEmit` 均通过，`npm run build` 构建成功。
- 运行中的服务（http://127.0.0.1:3003）已加载新构建，`AppLayout` 分包中 7 个管理端分组标题全部命中。
