# 支付宝正式支付接入

项目支持支付宝当面付扫码和网页收银台，使用官方 `alipay-sdk`，异步通知与主动查询均验签。此文对应当前代码；旧支付文档中的 `/payment/return`、修改源码切换网关等步骤不再适用。

网页表单的 CSP 白名单按环境允许支付宝官方域名及其收银台跳转；正式模式只允许 `https://*.alipay.com`，沙箱模式只允许 `https://*.alipaydev.com`，不会放开任意第三方表单目标。

## 先确认已开通的产品

开放平台入驻、应用上线和支付产品签约是不同步骤。请以正式应用后台实际开通的产品及接口权限为准。

| 已开通产品 | 配置 | 使用接口 |
| --- | --- | --- |
| 当面付扫码 | `ALIPAY_PAYMENT_MODE=qr` | `alipay.trade.precreate` |
| 电脑网站支付 / 使用 page.pay 的 AI 网页应用收款 | `ALIPAY_PAYMENT_MODE=web` | `alipay.trade.page.pay` |
| 上述两类均已开通 | `ALIPAY_PAYMENT_MODE=both` | 同时提供两种入口 |

网页支付收银台也可以包含二维码，并不等于应用已经签约当面付。请显式选择已开通的产品。留空仅为兼容旧配置：有回跳地址时显示两种方式，否则只显示扫码。

官方参考：[网页应用收款接入指南](https://aipay.alipay.com/docs/vibe-pay/ai-web-app-payment-qianyi/ai-web-app-payment-integration-guide.html)、[当面付快速接入](https://open.alipay.com/paymentServicer/paymentProvider.htm)。

## 正式环境参数

当前实现使用 RSA2 普通公钥模式。应用公钥上传至支付宝开放平台；应用私钥留在服务端；验签使用平台提供的“支付宝公钥”，不能用应用公钥替代。支持 PKCS#1、PKCS#8，支持 PEM 和原始 Base64。[官方 Node.js SDK 配置说明](https://github.com/alipay/alipay-sdk-nodejs-all#平台配置)

在服务器 `.env` 中填写以下参数。示例选择网页支付，APPID、PID、域名和密钥路径必须替换为实际值。

```dotenv
ALIPAY_ENV=production
ALIPAY_PAYMENT_MODE=web
ALIPAY_APP_ID=你的正式应用APPID
ALIPAY_SELLER_ID=收款支付宝账号的PID
ALIPAY_PRIVATE_KEY_FILE=/app/data/alipay/app-private.pem
ALIPAY_PUBLIC_KEY_FILE=/app/data/alipay/alipay-public.pem
ALIPAY_PRIVATE_KEY=
ALIPAY_PUBLIC_KEY=
ALIPAY_KEY_TYPE=
ALIPAY_GATEWAY=
ALIPAY_NOTIFY_URL=https://你的域名/api/payment/callback/alipay
ALIPAY_RETURN_URL=https://你的域名/api/payment/return/alipay
ALIPAY_USD_CNY_RATE=1.00
```

- Docker 部署：把密钥文件放在宿主机 `./data/alipay/`，已有数据卷会映射至 `/app/data/alipay/`。直接运行 Node 时填本机可读的路径。文件内容不会写入日志或返回给浏览器。
- 文件路径和对应内联密钥只能选一种。使用内联 PEM 时可用双引号包裹并以 `\n` 表示换行。
- PEM 可根据头部识别格式；原始 Base64 默认 PKCS#1，PKCS#8 原始字符串需显式写 `ALIPAY_KEY_TYPE=PKCS8`。
- `ALIPAY_SELLER_ID` 优先用于校验；未填 PID 时可以设置 `ALIPAY_SELLER_EMAIL`。至少配置一项。
- 正式网关留空时采用 `https://openapi.alipay.com/gateway.do`。正式模式不接受沙箱网关。
- `ALIPAY_NOTIFY_URL` 必须配置公网 HTTPS 地址，反向代理必须允许支付宝直接 POST 表单，不要在这条路径上要求用户登录或验证码。网页支付另需同步回跳地址；只开扫码可不填回跳地址。
- 充值比例含义是“每 1 USD 站内余额应付的人民币金额”。示例 `1.00` 沿用当前本地配置，即支付 1 元到账 1 USD 站内余额；留空默认 `7.20`。正式上线前确认业务定价。新订单保存应付人民币金额，后续比例变更不会改变旧订单金额。

本地 `.env.local` 与服务器 `.env` 隔离。仓库存在 `.env.local` 且不在 production 模式时，本地服务优先读取 `.env.local`；修改 `.env` 不会使本地服务自动切到正式支付。沙箱继续使用 `.alipay-sandbox.json`。

## 检查与部署

只检查指定环境文件的正式参数，验证密钥是否可解析、收款方和回调路径是否齐全，不连接数据库、不创建订单：

```sh
npm run pay:check -- --env-file .env
```

文件路径必须在运行该命令的环境内可读。Docker 配置中的 `/app/...` 应在容器内检查。服务器构建镜像后可以先运行一次检查：

```sh
docker compose build model-bridge
docker compose run --rm --no-deps model-bridge npm run pay:check -- --probe
docker compose up -d --no-deps model-bridge
```

`--probe` 只向正式网关查询随机订单号并验证响应签名。收到已验签的 `ACQ.TRADE_NOT_EXIST` 表明查询请求和验签链路可用；不会下单、支付、退款或写入钱包，也不证明支付产品已经签约或回调公网可达。

不使用 Docker 时，可在密钥路径适合本机的环境文件上执行 `npm run pay:check -- --env-file .env --probe`。显式指定的文件独立检查，不混入父进程的支付宝参数。

`npm run pay:smoke` 仅允许沙箱，会创建沙箱预订单，不能用于正式到账测试。

## 真实付款验收

1. 管理后台开启“在线支付”，用户账户中心充值入口只应出现已配置的支付宝产品。
2. 从用户充值页面创建一笔小额订单，核对支付宝展示的收款商户与人民币金额，由用户使用真实支付宝确认付款。
3. 验证订单转为已支付、钱包仅入账一次；服务器应对已验证且处理完成的通知返回纯文本 `success`。
4. 刷新订单或重复接收通知，钱包不应再次增加；如果浏览器没有返回网站，异步通知仍应完成入账。
5. 若异步通知未收到，可使用账户中心的支付状态查询补偿确认，并排查域名、HTTPS、反向代理和通知路径。

付款结果依据验签后的异步通知或服务端查询。同步回跳还会主动查单，不根据浏览器参数直接加余额。若配置检查失败，先修复对应参数再启用正式收款。

本次代码验证采用临时测试密钥和本地模拟网关，不代表真实商户已完成付款验收。正式 APPID、已开通产品、收款方身份、公网域名和正式密钥仍需由商户提供。
