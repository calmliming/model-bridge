# 上游账号余额查询说明（DeepSeek / Sub2API）

时间：2026-09-16 17:42:18

## 1. 背景

管理后台「账号管理」的「余额 / 配额」列，此前只有 Sub2API 账号能显示金额，DeepSeek 账号永远是「未更新」。

原因：该列的数据来自两类完全不同的上游接口，而实现只覆盖了其中一类。

| 账号类型 | 上游接口 | 返回内容 | 改造前状态 |
| --- | --- | --- | --- |
| Claude / OpenAI / MiniMax / Antigravity | 各自的额度接口或响应头 | 5 小时 / 7 天窗口百分比 | 正常 |
| Sub2API 中转站 | `GET /v1/usage` | Key / 订阅的剩余额度 | 正常 |
| DeepSeek 官方 | `GET https://api.deepseek.com/user/balance` | 钱包余额（含赠送额度） | **未接入** |

DeepSeek 账号使用普通 API Key，没有 OAuth 额度响应头，因此必须单独调用官方余额接口。

## 2. DeepSeek 余额接口

官方文档：<https://api-docs.deepseek.com/api/get-user-balance>

```http
GET https://api.deepseek.com/user/balance
Authorization: Bearer <API Key>
```

```json
{
  "is_available": true,
  "balance_infos": [
    {
      "currency": "CNY",
      "total_balance": "110.00",
      "granted_balance": "10.00",
      "topped_up_balance": "100.00"
    }
  ]
}
```

实现要点：

1. **金额是字符串**：`total_balance` 等字段为 JSON 字符串，必须转成数字后再入库，否则前端参与比较与格式化时会出错。
2. **`is_available` 表示可用性**：`false` 表示钱包已耗尽、上游拒绝调用，属于有效结果而非查询失败，需保留并单独展示。
3. **`granted_balance` 是赠送额度**：它是 `total_balance` 的组成部分，展示为「赠送」以区分充值余额。
4. **未返回已用金额**：`topped_up_balance` 只是充值部分，不能当作「已用」，因此不写入 `used` 字段。
5. **只访问官方域名**：与中转逻辑一致，不读取账号上的 Base URL；`api.deepseek.com` 已在 `src/http/urlGuard.ts` 白名单内。

## 3. 代码结构

新增的通用余额模块与提供方实现分离：

| 文件 | 职责 |
| --- | --- |
| `src/providers/balance.ts` | 通用余额类型、数值/时间解析、快照校验回读、单行摘要、余额型服务商清单 |
| `src/providers/deepseek/balance.ts` | DeepSeek `/user/balance` 请求与响应解析 |
| `src/providers/sub2api/balance.ts` | Sub2API `/v1/usage` 及兼容端点解析（复用通用原语） |
| `src/accounts/tester.ts` | 余额型账号的刷新入口，与既有配额刷新共用同一条链路 |
| `web/src/views/AccountsView.vue` | 「余额 / 配额」列渲染与自动刷新 |

余额型服务商清单只有一处权威定义：

```ts
// src/providers/balance.ts
export const BALANCE_PROVIDERS = ['sub2api', 'deepseek'] as const
```

前端无法直接 import 该模块（会连带打包 Node 专用的 URL 校验代码），因此在视图内保留一份同名清单，并由 `web/balance.test.ts` 读取两侧源码做一致性断言，避免后续加服务商时漏改。

## 4. 存储与兼容

- 余额快照写入账号 `metadata.upstreamBalance`，形如：

  ```json
  {
    "upstreamBalance": {
      "provider": "deepseek",
      "endpoint": "/user/balance",
      "currency": "CNY",
      "totalBalance": 110,
      "granted": 10,
      "remaining": 110,
      "available": true,
      "updatedAt": 1789000000000
    }
  }
  ```

- 改造前 Sub2API 的快照写在 `metadata.sub2apiBalance`。读取时先取 `upstreamBalance`，取不到再回退到旧键，因此**升级后不需要刷库**，历史 Sub2API 余额仍能显示，下一次刷新会自动写入新键。
- 回读时逐字段校验（数值有限、`updatedAt > 0`、模式枚举），半写入或损坏的快照一律视为「无数据」，不会显示成「余额 $0」。

## 5. 刷新行为

1. **进入账号页**：`/admin/accounts` 返回 `balance` 字段；快照超过 5 分钟未更新的余额型账号会走 `POST /admin/accounts/batch-quota-refresh` 自动刷新，失败后 5 分钟内不重复重试（与改造前的 Sub2API 行为一致，现在同样覆盖 DeepSeek）。
2. **点击单元格刷新按钮**：余额型账号只调用只读的余额接口，不再先发一次连通性探测——这样即使钱包耗尽、上游拒绝推理请求，也仍能查到并显示余额。按钮文案由「刷新配额」变为「刷新余额」。
3. **点击「测试」按钮**：连通性探测成功后顺带查询一次余额并落库；余额查询失败**不会**让测试结果变成失败，仅在没有任何历史快照时显示「等待查询 DeepSeek 余额」。

## 6. 展示效果

DeepSeek 账号的单元格显示：

```
剩余 ¥110.00
DeepSeek 钱包余额 · 总额 ¥110.00 · 赠送 ¥10.00
```

- 颜色：剩余额度不足总额 20% 为橙色，为 0 或 `is_available: false` 为红色（并显示「余额不足 · 剩余 ¥0.00」），其余为绿色。
- 币种：按上游返回的 `currency` 使用 `Intl.NumberFormat` 渲染，CNY 显示 `¥`，USD 显示 `$`。
- Sub2API 账号保持原有展示（含订阅窗口、重置/到期时间），仅样式类名由 `sub2api-balance-*` 统一为 `upstream-balance-*`。
