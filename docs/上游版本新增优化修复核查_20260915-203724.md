核查日期：2026-09-15。

> 2026-09-16 复核修复：撤回本地 Pro → Flash 自动计价切换；规范化 DeepSeek 的 `[1m]` 后缀和大小写；模型目录改为在合并与映射后按实际提供方校验；为批量操作的列表刷新补齐超时。本文原核查过程保留，最新结果见末尾补充。

- 方法：读本地路由、转发器、计费、运维统计与管理界面源码，与发布说明逐条比对。判定「已覆盖」只表示本地存在对应逻辑，不代表在所有协议边界上与上游等价；本轮没有生产环境测试。

## 结论

v0.2.5 的三类改动里，**大部分修复项在 model-bridge 已经不成立**——要么本地早已实现正确行为，要么依赖上游独有的架构（Go + Redis + OpenAI WebSocket 连接池）。

真正值得动手的只有 5 项，均为小改动：DeepSeek 模型名兜底校验、Gemini 3.7 Flash 目录与价格缺失、费用精度 6 位、请求详情不展示 TTFT、订阅 / API Key / 用户三处缺批量操作。

两项较大的新功能——OpenCode 平台接入与站点类型三态开关——属于产品定位选择，不是缺陷。

自检修正（实施后复查发现）：

1. **DeepSeek 白名单收紧**。初版把 `deepseek-v4.1-pro` 和 `deepseek-v4-flash-thinking` 也列入白名单，依据是 `pricing.ts` 的 substring 匹配注释。但那两处是**计价容错**（数据库可能存旧行、入参可能是新名），不证明上游 API 当前接受这些名字。上游本次修复的要点恰是“按官方名单严格校验”，故将两移出白名单，并补测试断言它们会被拒绝。
2. **批量删除套餐的文案有误**。原写“已分配给用户的订阅不受影响”。实际 `resolveActiveSubscription()`（`subscriptions/manager.ts:112`）内联 JOIN `subscription_plans` 取日/周/月限额，删除套餐后该 JOIN 返回空，已生效订阅会静默降级为余额扣费。两处确认文案已改为提示“已生效订阅会因套餐缺失而改走余额扣费，建议先改为下架”。
3. **8 位精度与钱包微美元的关系**。~~钱包按整数微美元（1e6）记账，`usdToMicros()` 会把不足 1 微美元的尾数舍入；8 位精度只落在 `usage_logs.cost` 的 doublePrecision 列上，对实际扣费无影响。改动在记账层名副其实，扣费层维持原舍入，无需改动。~~

   **上述结论有误，此处更正。** 改动前 `cost` 恒为 1e-6 的整数倍，因此 `usdToMicros(cost)` 与记录值**精确相等**——这条不变量正是 1e8 改动悄悄删掉的。现在三个账本（`usage_logs.cost`、`api_keys.quota_used`、`wallet_transactions.amount_micros`）在亚微美元量级互相矛盾，且**两个方向都会错**：

   - `cost = 3e-7` → `Math.round(0.3) = 0` → 不写钱包流水、余额不减，但 `usage_logs.cost` 与 `quota_used` 都记了 → **系统记了成本却收 0**；
   - `cost = 6e-7` → 实扣 1e-6 → **比记录值多收 67%**。

   连带后果：`quota_used` 会被从未真正扣费的请求耗尽（`apiKeyAuth` 以 `quota_used >= quota_limit` 拒绝），用户看到的「已用」与余额变化对不上；`SUM(usage_logs.cost)` 与 `SUM(wallet_transactions.amount_micros)/1e6` 之间出现随流量增长、永不回补的差额。`subscriptions/manager.ts:209` 那句「Costs are rounded to micro-USD before this function is called」的注释也已与数据不符。

- **批量删除用户**：model-bridge 后端目前完全没有删除用户的能力（无 `deleteUser`，无 `DELETE /admin/users/:id`）。`api_keys`、`usage_logs`、`wallet_transactions`、`subscriptions` 等六张表以 `user_id` 关联且无外键级联约束，删除需要先定义级联或软删策略，属于独立功能而非本次修复，未擅自实现。

## 本轮复核与修复

对上述工作做了一次独立代码审查（含跨文件追踪与逐条验证），发现 17 处问题并修复。按严重程度：

### 已修：确定性缺陷

1. **套餐页批量操作条无样式**。`SubscriptionPlansView.vue` 的 `<style scoped>` 整块只有 `.toolbar` 与 `:deep(.subtext)`，而模板用到了 `fade`/`bulk-actions`/`bulk-summary`/`count-badge`/`bulk-buttons` 五个类。这些类只定义在 `ApiKeysView.vue` 自己的 scoped 块里（不外溢），`count-badge` 更是全仓无定义。已把批量操作条提升为 `web/src/styles.css` 的全局类（含 dark 模式覆盖，取自 `AccountsView.vue` 的超集版本），三个视图共用一份。

2. **DeepSeek 三个入口行为分裂**。见 3.3 第 1 条更正。`mapResponsesModel` 已改为委派 `mapModel`，并补测试断言两者对任意输入（含被拒名）结论一致。

3. **新抛异常的落点**。`DeepseekRequestError` 原本抛在 `executeRelay` 的 `try` 块**之外**、并发闸门之前，只能由 Fastify 默认 errorHandler 兜底：错误体不符合任何协议信封（SDK 只能解析成通用报错），且不写 `usage_logs`，管理端看不到这类失败。现已就地捕获并按仓库既有的 `{ error: { type: 'invalid_request_error', code, message } }` 信封返回。

   顺带发现 `validateAntigravityModel` 抛的 `AntigravityRequestError` 在**同一位置**有同样问题。因为仓库里有 12 个类共用「`statusCode` + `code`」约定，改用结构化判断 `isClientModelError` 一次覆盖，避免以后新增 provider 时再漏。

4. **Gemini 3.7 的 sanitize 门禁**。原判据写死 `startsWith('gemini-3.8-flash')`，新上线的 3.7 不命中。查证后确认 3.7 Flash 于 2026-08-13 发布时引入了与 3.8 相同的破坏性变更（不再接受 `temperature`/`top_p`/`top_k`/`candidate_count`，`thinking_budget` 改为 `thinking_level`），已把判据扩为 `/^gemini-3\.[78]-flash/` 并补测试。

   这条不是边缘情况：antigravity 路径会**主动合成**数值 `thinkingBudget`（`antigravity/converter.ts:104`）再送进 sanitize，所以只要开启 thinking，发往 3.7 的请求**每次**都带它。

5. **发现层公告自己会拒绝的模型名**。deepseek 账号目录**每 6 小时自动同步**且 `providerModels` 被上游目录整体覆盖，因此上游 `/models` 返回的任何名字都会被列进 `GET /v1/models`，而其中不在白名单里的名字被客户端拿去调用时直接 400。已新增 `isForwardableDeepseekModel()` 并在 `listModelIdsForKey` 中过滤。

6. **批量删除把 200 一律计成功**。单条 `DELETE /admin/keys/:id` 对不存在的 id 也返回 200——根因在服务端：`deleteApiKey` 不检查影响行数。已改为用 `.returning()` 返回删除行数，两个删除路由在 0 行时返回 404。

7. **批量操作的整体重做**。原实现有三处问题：串行发 N 个请求（200 个 Key = 200 次串行 HTTP + 200 次 JWT 校验）；共享 axios 实例**没有超时**，任一请求挂住会让 `finally` 永不执行、`bulkBusy` 永久锁死，只能刷新页面；部分失败后清空整个选择集，既不显示失败项也无法重试（而 `AccountsView` 的正确行为是只保留失败项）。

   已抽出 `web/src/composables/useBulkSelection.ts`，提供有界并发 + 每请求超时 + 逐条结果收集 + 只保留失败项，两个视图共用。行复选框另外接上 `UiDataTable` 既有的 `rowCheckable`，批量进行中禁止改选（此前取消不生效、新增被静默跳过）。

8. **重复代码收敛**。9 份本地 `formatUsd`（其中 7 份逐字节相同）统一到 `utils.ts`；3.6/3.7 两张广场卡片改为由同一份定义派生（与文件里 `flare`/`sunburst` 的既有写法一致），避免推广价与 2027 年切换点逐卡手抄改漏。

### 已修：计费精度收敛（记账回 1e-6）

见「自检修正 3」的更正。**决定：记账精度回到微美元（1e-6）**——钱包是整数微美元，根本表示不了一微美元以下的金额，所以「让廉价请求不再被记为 0」这个初衷靠提高记账精度实现不了，只能靠改钱包单位（需数据迁移）。选择恢复一致性，而不是引入单位变更。

实现上没有再散写字面量：`roundUsd()` 加在 `src/wallet/money.ts` 与 `MICRO_USD` 同处，`pricing.ts`（`cny`、`estimateCost`）、`stats.ts`、`recorder.ts` 四处统一调用它，并在注释里写明「每个记录或扣款的账本都必须在这里取整，否则三个账本会漂移」。这是本次问题的根因——原来四处各写各的 `1e6`/`1e8` 字面量，改一处就会失配。

代价是明确的：低于 1 微美元的请求仍记为 0。这是诚实的——钱包收不了这个钱；比记了成本却收 0（或多收 67%）要好。

配套：展示层改为按量级自适应位数（`utils.ts` 的 `formatUsd`），因为 `cost` 落在 1 微美元到 1 分之间时，原来的固定 4/6 位会把它显示成 `$0.0000`，读起来像免费。
