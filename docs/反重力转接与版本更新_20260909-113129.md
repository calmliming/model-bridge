# 反重力转接与版本更新

日期：2026-09-09。版本：model-bridge `0.2.0`。

## 接入结论

按用户选择，通过已有 Sub2API 转接 Antigravity，不在本项目新增 Antigravity 原生 OAuth 账号。

调用链为：客户端 → model-bridge → 已有 Sub2API → Google Antigravity。Google 登录、账号资格与 Google 侧网络出口由上游 Sub2API 管理。只要 model-bridge 能访问该网关，其自身不需要直接请求 Google。

这能把 Google 侧网络依赖放到上游服务器，但不能保证消除地区限制。Google 官方 FAQ 同时要求支持地区和符合资格的账号，并指出需检查账号关联国家/地区。代理出口与账号地区不是同一条件。官方也未将第三方转接 Antigravity 登录列为受支持用途；本次实现的是 Sub2API 兼容路径。

## 配置步骤

1. 在上游 Sub2API 完成 Antigravity 授权及连通性测试，为对应分组创建 API Key。
2. 在 model-bridge 的「上游账户」添加 **Sub2API** 账户；API Key 填上游密钥，Base URL 填 `https://你的上游/antigravity`。
3. 将此账户放入独立分组，本项目的客户端 Key 绑定该分组，服务商限制选择 `sub2api`。避免与原生 Claude 或原生 Gemini 账号共用同一会话。
4. 客户端使用 model-bridge 生成的 `mb-...` 密钥，不能把上游密钥填成客户端密钥。

| 客户端协议 | model-bridge 入口 | 上游专用路径 |
| --- | --- | --- |
| Gemini JSON | `/api/sub2api/v1beta/models/{model}:generateContent` | `/antigravity/v1beta/models/{model}:generateContent` |
| Gemini SSE | `/api/sub2api/v1beta/models/{model}:streamGenerateContent` | 同路径，追加 `?alt=sse` |
| Gemini 模型列表/详情 | `/api/sub2api/v1beta/models`、`/api/sub2api/v1beta/models/{model}` | 本地按 Key 和分组策略生成 Gemini 格式目录 |
| Anthropic Messages | `/api/sub2api/v1/messages` | `/antigravity/v1/messages` |

Gemini SDK 的 Base URL 可填 `https://你的-model-bridge/api/sub2api`；若 SDK 配置项本身要求包含版本，则填到 `/api/sub2api/v1beta`。最终请求路径应与上表一致。

当 Key 仅允许 `sub2api` 时，通用 `/v1beta/models/*` 及模型发现请求也走 Sub2API。显式 `/api/gemini/*` 保留原生 Gemini 语义。

Base URL 的 `/antigravity` 前缀会被保留，尾部 `/v1` 或 `/v1beta` 会归一化，避免重复拼路径。

### Codex / Chat Completions

核查 Sub2API 主线路由后确认，专用 `/antigravity/v1` 只注册 Messages、count_tokens、models、usage，不注册 Chat Completions 或 Responses。

若要通过这些协议调用 Antigravity，请将该上游账户的 Base URL 设为 **Sub2API 根地址**，并在上游将 Key 绑定到 Antigravity 分组。若仍使用 `/antigravity` 专用前缀，本项目返回明确的 `antigravity_endpoint_unsupported`，不会发起无效请求或因此冷却账号。

## 本轮修复

- 补齐 Sub2API 的 Gemini 原生 JSON/SSE 转发，保持 Gemini 响应格式和历史 thoughtSignature，不注入 Code Assist 的 project 包装。
- 原生与转接 Gemini 均先展开工具 schema 中的本地 `$ref`，再清理不兼容字段。保留引用对象的参数、required 和描述。未解析、远程、递归或超过展开预算的 schema 返回客户端 400，不惩罚上游账号；不主动抓取远程 schema。
- Gemini 输出费用包含 `candidatesTokenCount + thoughtsTokenCount`；`reasoningTokens` 仍单独展示但不重复计费。缓存读取继续从总输入中拆分。此前已保存的历史账单不回算。
- 对明确的 Google 地区错误返回 `google_location_unsupported`。只冷却命中的本地上游账户并尝试其他账户；候选耗尽时保留地区诊断，不替换为笼统的无可用账号提示。普通权限错误或工具参数错误不会仅因出现 location 一词被视为地区限制。
- 本地 Gemini 入口只接受 generateContent、streamGenerateContent、countTokens，防止任意 action 被转发到 Code Assist 内部接口。
- 原生 Gemini OAuth 的换码、刷新和项目查询接入超时、重定向保护与错误脱敏；保留刷新令牌、项目标识和返回的套餐标识，缺少资格/项目时提供明确提示。
- Gemini 连通性测试复用项目查询逻辑，Docker Compose 补传 `GEMINI_OAUTH_CLIENT_ID` 和 `GEMINI_OAUTH_CLIENT_SECRET`。通过 Sub2API 转接不要求配置这两个本地变量。

## 版本

`package.json`、`package-lock.json` 的根版本与 package 条目、HTML 演示版本均从 `0.1.183` 更新到 `0.2.0`。后端版本读取已验证为 `0.2.0`。

版本徽标优先使用正在运行的后端版本；更新服务提供的 Git checkout 版本仅作为回退，避免本地新代码仍显示旧提交版本。此次版本同时包含上一轮 MiniMax、分组白名单和稳定性改进；没有创建 Git tag、GitHub Release 或执行生产部署。

## 验证与边界

- 全量测试：74 个文件、619 项通过；4 项独立数据库测试本轮默认跳过，已在前一轮临时 PostgreSQL 中通过。
- 后续模型发现入口回归：relay 集成文件 39 项通过；OAuth/专用协议回归 13 项通过。
- 前后端类型检查与前端生产构建通过；package 与 lock 版本一致，版本读取接口使用同一数据源。
- 使用真实 loopback HTTP 客户端和模拟上游验证了 JSON、SSE、签名保留、额度记录、地区故障隔离、换号、最后错误保留和分组限制。
- 没有获取或使用真实 Sub2API/Google 凭据；Google 实际资格、上游代理出口和所选模型可用性仍需在部署环境验证。
